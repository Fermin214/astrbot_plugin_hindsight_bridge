# 在 AstrBot 中安装与配置

这份指南适用于已经能用 QQ 与 AstrBot 正常聊天的使用者。安装完成后，记忆会在日常聊天中自动积累和使用。

## 先准备记忆服务

你需要 Hindsight **1.1.0** 的两个信息：

- **API 地址**：AstrBot 用来连接记忆服务的地址。
- **API Key**：连接记忆服务的密钥。

如果由别人维护服务，请向维护者索取这两个值。如果自己搭建，先按 [部署 Hindsight](../deploy/README.md) 完成服务安装，再回到这里。

插件适配 AstrBot **4.29.1**、内置执行器 `local` 和 **OneBot v11 的 QQ 私聊**。其他组合见 [兼容范围](SUPPORT.md)。

## 一、安装插件

1. 打开 AstrBot 网页管理面板，进入 **插件管理**。
2. 点击 **安装**，选择 **从链接安装**。
3. 粘贴仓库地址并安装：

   ```text
   https://github.com/Fermin214/astrbot_plugin_hindsight_bridge
   ```

4. 安装完成后，在已安装列表找到 **Hindsight Memory**，点击 **配置**。

AstrBot 会自动安装插件依赖。正常安装无需下载源码、执行 Python 命令或手动复制插件文件。

## 二、取得自己的账号信息

在 **QQ 私聊**里给机器人发送：

```text
/sid
```

这是 AstrBot 自带的账号信息命令，回复中会包含：

```text
UID: 「123456789」
Bot ID: 「my-onebot」
```

示例中的两个值对应：

| 插件里的字段 | 从哪里复制 | 示例 |
| --- | --- | --- |
| 平台实例 ID | `/sid` 回复里的 **Bot ID** | `my-onebot` |
| 用户 ID | `/sid` 回复里的 **UID**，即发消息者自己的 QQ 号 | `123456789` |

只复制括号里的内容。这里的 **Bot ID 是 AstrBot 的接入实例标识**，不是机器人登录的 QQ 号。也可以在 AstrBot 的消息平台配置中找到该 OneBot 接入的 `id`。

## 三、填写插件配置

| 界面中的配置项 | 填写方式 |
| --- | --- |
| 启用记忆 | 填完其他内容后打开 |
| Hindsight API 地址 | 填记忆服务地址，地址选择见下一节 |
| Hindsight API Key | 填服务 API Key，不是模型 API Key，也不是 Hindsight 网页登录 Key |
| 稳定服务标识 | 自己起一个名字，例如 `home-hindsight`；同一套服务一直沿用 |
| 消息时区 | 中国大陆填 `Asia/Shanghai`，香港填 `Asia/Hong_Kong` |
| 允许使用记忆的平台账号 | 点击新增，分别填上一步取得的平台实例 ID 和用户 ID |

**其他项目保持默认即可。** “独立控制目录”可以留空，插件会自动创建；AstrBot 的数据目录需要像平常一样持久保存。

要给其他人使用，就为每个人增加一项账号。账号列表为空时，所有人都不启用记忆；在多个 OneBot 接入中使用同一 QQ 号，也要分别填写对应的组合。

“稳定服务标识”只是这套记忆服务的固定名称，无需去其他页面申请。已有记忆后不要随意修改它或“稳定 Agent 标识”；搬迁同一服务见 [备份与恢复](DATA-MAINTENANCE.md)。

### API 地址怎么填

以仓库提供的部署模板为例：

| AstrBot 和 Hindsight 的安装位置 | 填什么 |
| --- | --- |
| 两者在同一 Docker 主机，并加入模板的客户端网络 | `http://hindsight:8888` |
| AstrBot 直接运行在主机上，Hindsight 在这台主机的 Docker 中 | `http://127.0.0.1:8888` |
| 两者在不同主机 | 填维护者提供的、AstrBot 能访问的 HTTPS API 地址 |

Hindsight 的 `9999` 端口是网页管理面板，插件要连接的是 **API 的 `8888` 端口**。实际部署修改过端口时使用实际值。

Docker 中的 AstrBot 不能用 `127.0.0.1` 访问另一个容器。两者分属不同 Compose 项目时，需要先让它们加入同一网络，步骤见 [让 AstrBot 容器连接 Hindsight](../deploy/README.md#让-astrbot-容器连接-hindsight)。

使用仓库模板时，打开后端 `deploy` 目录的 `.env`，复制 `HINDSIGHT_API_TENANT_API_KEY=` 后面的值到插件 **Hindsight API Key**。

## 四、设置 AstrBot 对话选项

进入 AstrBot 的 **配置文件**，打开这位 QQ 用户使用的配置，选择 **AI**，按界面上的名称设置：

| 设置 | 使用的值 |
| --- | --- |
| Agent 执行方式 → 执行器 | 选择 **内置 Agent** |
| 其他配置 → 现实世界时间感知 | 关闭 |
| 其他配置 → 用户识别 | 关闭 |

“内置 Agent”对应 `local`，是 AstrBot 的执行方式，聊天仍使用你已配置的模型。后两项会给消息附加文字；关闭它们，插件才能把用户消息与机器人保存的会话历史正确对应。设置后保存配置。

如果为不同用户指定了不同配置文件，要修改这段 QQ 私聊实际使用的那份。

## 五、保存并开始使用

打开插件配置中的 **启用记忆**，保存配置，回到插件列表并 **重载** Hindsight Memory；插件在列表中也应处于启用状态。

之后直接与机器人正常聊天。保存记忆和查找相关记忆都自动进行，切换会话也会继续使用已有记忆。

日常管理见 [使用指南](USAGE.md)。`/hindsight status` 用于查看连接或排查问题，`/hindsight view` 用于查看记忆内容。

## 常见问题

### 显示“私聊未开放记忆”

检查插件列表中的启用状态，以及插件配置里的“启用记忆”。再核对允许账号中的两个值是否与这段 QQ 私聊的 `/sid` 回复一致，保存并重载。

### 提示“无法连接后端”

检查 API 地址和 Hindsight 的运行状态。Docker 部署最常见的问题是填了 `localhost`，或 AstrBot 尚未加入后端网络。

### 提示“API Key 无效”或“后端未启用认证”

使用服务 API Key。仓库模板中是 `HINDSIGHT_API_TENANT_API_KEY`；`HINDSIGHT_CP_ACCESS_KEY` 只用于浏览器登录管理面板。使用已有后端时，请维护者开启 API Key 认证。

### 提示“执行器尚未适配”

进入这段 QQ 私聊使用的 **配置文件 → AI → Agent 执行方式**，把执行器改为 **内置 Agent**。Dify、Coze 等执行器没有接入这套自动记忆流程。

### 刚聊完，列表里还没有记忆

记忆在后台整理，不会立即显示。短时间内仍然为空时，可用 `/hindsight status` 查看待处理数量和错误提示。确认处于“开启”模式、账号填写正确，且消息是普通私聊文字；群聊、媒体消息和命令不自动记录。

### 插件安装失败或出现在“加载失败插件”中

在 AstrBot 插件页面展开错误信息。下载失败检查运行 AstrBot 的主机能否访问 GitHub；依赖安装失败查看 AstrBot 日志里的具体包名和错误。需要维护者处理时，提供错误文字和 AstrBot 版本。

### 导出 JSON 文件失败

当 AstrBot 和 OneBot 程序运行在不同容器时，OneBot 程序可能无法读取 AstrBot 生成的文件。请在 AstrBot **系统配置**中填写 **对外可达的回调接口地址**（`callback_api_base`），使用 OneBot 能访问的 AstrBot 后端地址，例如同一网络中的 `http://astrbot:6185`。

也可以由维护者配置双方都能读取的共享文件路径。此设置影响文件传输；普通文字聊天与自动记忆不需要先发送测试文件。

### 提示需要恢复控制目录

这是数据挂载或备份恢复问题，按 [备份与恢复](DATA-MAINTENANCE.md#异常提示) 找回匹配的控制目录。

## 配置文件示例

通过网页填写配置即可。需要批量部署或手动编辑配置文件时，可参考 [config.example.json](../examples/config.example.json)，替换地址、Key 和账号，再打开 `enabled`。
