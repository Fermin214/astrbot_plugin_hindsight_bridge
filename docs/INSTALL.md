# 安装与连接

适用于 Linux、AstrBot 4.29.1、内置 Agent 和 OneBot v11 私聊。配套服务主机需安装 Docker Engine 与 Compose v2。

## 一、安装插件

在 AstrBot 的 **插件管理 → 安装 → 从链接安装** 填写：

```text
https://github.com/Fermin214/astrbot_plugin_hindsight_bridge
```

依赖安装完成后，打开 **Hindsight Memory 插件详情 → 记忆管理 → 设置**。面板只有「记忆管理」和「设置」两个标签；连接、模型、使用者、运行状态与服务维护都在设置中。

## 二、安装或连接记忆服务

### 安装配套服务

1. 选择 **安装配套记忆服务**，点击 **生成安装命令**。
2. 点击 **复制并隐藏**，在运行 AstrBot 的 Linux 主机终端执行。
3. 终端显示安装完成后，回到设置，点击 **检查连接**。
4. 在出现的模型配置区选择 AstrBot 已配置的聊天与嵌入模型，可选重排模型，点击 **检查并保存模型**。

安装命令部署数据库、Hindsight、服务管理接口和必要的协议转换组件，自动生成服务连接凭据与独立标识。模型密钥经后台配置接口传给配套服务，保存在该服务的私有设置卷中。

命令只在生成时展示；复制、离开设置、切换窗口或关闭页面后清除。安装完成后，安装入口收起。需要修复或更新服务文件时，从 **服务维护 → 重新生成安装命令** 操作；重复安装沿用服务身份和数据。

配套服务的连接密钥由插件自动保存，无需填写。AstrBot 运行在 Docker 中时，服务接入 AstrBot 已有网络，管理接口无需发布主机端口。原生部署只将 API 与管理端口绑定到本机回环地址。

### 连接已有 Hindsight

选择 **连接已有 Hindsight**，填写服务 API 地址与连接密钥，点击 **检查连接**。API Key 用于插件访问记忆服务，与模型供应商的密钥不同。

服务端口通常为 `8888`；Hindsight 自带网页端口 `9999` 不能用作 API 地址。AstrBot 在 Docker 中时，`127.0.0.1` 指向 AstrBot 容器自身。

已有服务的模型由该服务维护。手工部署见 [Linux 部署说明](../deploy/README.md)。

## 三、选择使用者并完成设置

1. 选择 QQ 机器人对应的接入实例，填写发消息者自己的 QQ 号；多人使用时分别添加。
2. 确认浏览器自动读取的消息时区。`Asia/Shanghai` 与 `Asia/Hong_Kong` 都是 UTC+08:00，可按所在地选择；时区用于解释今天、明天等相对日期。
3. 点击 **完成设置**，之后正常聊天即可。

列表只开放明确添加的实例与账号组合。清空列表后，没有账号使用记忆。保存立即生效，页面转到记忆管理。总开关使用 AstrBot 插件面板的启停；关闭插件停止采集、召回和插件侧队列，后端已接收任务可继续完成。

## 四、服务维护与卸载

配套服务的模型、运行状态与重新部署入口位于设置。模型连接检查通过后直接保存生效，无需重新生成安装命令；更换嵌入模型、参数或维数需要迁移已有向量数据。

在 **设置 → 服务维护** 确认删除全部记忆数据后，可生成完整卸载命令，在原安装主机执行。命令按安装标识检查目录与资源，只删除这套配套服务的容器、专属网络、数据卷和安装文件。共享镜像、Docker、AstrBot 和其他服务不属于卸载范围。插件本体在 AstrBot 插件面板卸载。

已有 Hindsight 不提供服务卸载操作。

## 常见问题

### 找不到「记忆管理」视图

检查 AstrBot 版本是否为 4.29.1，插件是否安装成功并处于启用状态。更新插件后可先重载，再重新打开插件详情。

### 模型列表中没有嵌入模型

普通对话模型不能替代嵌入模型。到 AstrBot **模型供应商 → 嵌入** 添加模型，保存后返回插件点击「刷新状态」。无需在插件里再次输入模型 Key。

### 供应商显示不兼容

向导支持 OpenAI Chat、Responses、Claude、Gemini，以及百炼和 Ollama 原生嵌入。常用代理、请求头和额外参数可以沿用。模型类型未知、使用多模态嵌入或请求参数覆盖记忆处理所需字段时，会显示具体原因，见 [模型兼容范围](SUPPORT.md#模型供应商复用)。

### 安装命令提示无法使用 Docker

请在服务器主机的终端执行，不要在 AstrBot 容器内部执行。Docker Engine 和 Compose v2 需要安装完成，执行命令的账号需要有 Docker 使用权限。

### 安装时下载或构建失败

终端会显示 Docker 的具体错误。检查服务器到镜像仓库及软件源的网络后，重复执行同一条安装命令。重复执行沿用服务身份和数据库。

### 提示无法连接后端

配套安装需在运行这套 AstrBot 的 Docker 主机执行。已有服务请检查 API 地址、端口和网络是否可达；Docker 容器之间一般使用服务名称，而不是 `localhost`。

### 模型地址使用 localhost

配套记忆服务在独立容器中运行，不能直接复用指向 AstrBot 自身的 `localhost`、`127.0.0.1` 或 `::1`。请在 AstrBot 模型供应商中使用记忆容器也能访问的服务地址。Docker 中的模型可使用共享网络内的服务名称；仅监听宿主机回环地址的模型，需要先调整监听地址和容器网络。

### 提示 API Key 无效或后端未启用认证

配套安装的 Key 自动交接。连接已有服务时，使用服务 API Key，并请维护者确认已启用认证。服务 Key 与 Hindsight 网页登录 Key 不同。

### 提示执行器不支持

在所选 QQ 用户使用的 AstrBot **配置文件 → AI → Agent 执行方式**中选择 **内置 Agent**。Dify、Coze 等执行器没有接入自动记忆流程。

### 保存后还看不到记忆

账号从启用后的新消息开始记录。后台需要整理时间，列表不会立即更新；可以到「设置」查看运行状态、待办和错误。群聊、媒体和命令不自动记录。

### 导出 JSON 文件失败

管理员可直接在插件管理视图下载 JSON，无需经 QQ 传输。

使用私聊 `/hindsight export` 时，AstrBot 与 OneBot 分容器可能需要配置文件回调地址。在 AstrBot **系统配置**填写 OneBot 能访问的 `callback_api_base`，例如同网络的 `http://astrbot:6185`，或由维护者设置共享文件目录。

### 提示需要恢复控制目录

按 [备份与恢复](DATA-MAINTENANCE.md#异常提示) 恢复匹配的控制目录。
