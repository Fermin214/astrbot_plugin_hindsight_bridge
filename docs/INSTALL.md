# 安装与连接

需要 AstrBot **4.29.1 及以上**，使用内置执行器 `local`、OneBot v11（`aiocqhttp`）QQ 私聊纯文字和 Hindsight **1.1.0**。目前支持 Linux 服务端，默认在同一台服务器部署：AstrBot 可原生运行或使用 Docker 桥接网络，Hindsight 使用 Docker。配套服务主机需安装 Docker Engine 与 Compose v2。

## 一、安装插件

在 AstrBot 的 **插件管理 → 安装 → 从链接安装** 填写：

```text
https://github.com/Fermin214/astrbot_plugin_hindsight_bridge
```

依赖安装完成后，打开 **Hindsight Memory 插件详情 → 记忆管理 → 设置**。面板有“运行管理”和“设置”两个标签：设置用于安装、连接、选择模型和添加使用者；运行管理用于查看状态、管理用户记忆和保存任务。

## 二、安装或连接记忆服务

### 安装配套服务

1. 选择 **安装配套记忆服务**，点击 **生成安装命令**。
2. 点击 **复制命令**，在运行 AstrBot 的 Linux 主机终端执行。
3. 终端显示安装完成后，回到下方的模型配置区。
4. 选择 AstrBot 已配置的聊天与嵌入模型，可选重排模型，点击 **验证并保存模型**。页面显示验证与启动进度，完成后提示服务连接正常。

安装命令部署数据库、Hindsight 及其官方管理页面（Control Plane），自动生成连接密钥。Hindsight 和官方页面固定为 1.1.0，使用原生管理功能。网页登录密钥与插件连接服务的 API Key 不同。所选模型的连接信息保存在配套服务的模型配置卷中。

复制、关闭、离开设置或隐藏页面后，含凭据命令会清除展示，需要时重新生成。安装入口和模型选择始终可用；服务尚未安装时，保存模型会提示先执行安装命令。需要修复或更新服务文件时，使用 **服务维护 → 生成重新部署命令**；重复执行沿用服务身份和数据。

配套服务的连接密钥由插件自动保存，无需填写。AstrBot 运行在 Docker 中时，服务接入 AstrBot 已有网络；主机开放的端口只监听 `127.0.0.1`，不能从管理员电脑直接访问。官方页面的反向代理、SSH 隧道、端口及密钥操作见 [Linux 部署说明](../deploy/README.md#五打开官方-control-plane)。

### 连接已有 Hindsight

选择 **连接已有 Hindsight**，填写服务 API 地址与连接密钥，点击 **测试服务连接**。此操作检查地址与服务密钥是否可用，不验证或保存模型。API Key 用于插件访问记忆服务，与模型供应商的密钥不同。

服务端口通常为 `8888`；Hindsight 自带网页端口 `9999` 不能用作 API 地址。AstrBot 在 Docker 中时，`127.0.0.1` 指向 AstrBot 容器自身。

在“官方管理地址”填写管理员浏览器可访问的地址，配置项为 `control_plane_url`。API 地址和官方管理地址分别保存，不按端口自动推导。已有服务需提供同为 1.1.0 的原生官方管理页面，网页登录密钥由服务维护者提供；模型也由该服务维护。手工部署见 [Linux 部署说明](../deploy/README.md)。

### 独立访问官方 Control Plane

服务器上的官方页面需要 HTTPS 域名反向代理或 SSH 隧道。浏览器里的 `127.0.0.1` 指管理员自己的电脑，不是服务器；直接输入服务器的环回地址无法访问远程面板。

有域名时，为官方页面配置独立 HTTPS 地址，例如 `https://memory.example.com`。无域名时，在管理员电脑执行：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:9999:127.0.0.1:9999 your-user@your-server
```

替换服务器登录信息并保持终端打开，将 **官方管理地址** 填为 `http://127.0.0.1:9999`。端口改动和反向代理示例见 [部署说明](../deploy/README.md#五打开官方-control-plane)。这些设置不改变插件的 API 地址。

配套安装的登录密钥保存在服务器安装目录的 `.env`。在安装时使用的同一服务器账号下执行，`<id>` 替换为安装输出中的服务编号：

```bash
sed -n 's/^HINDSIGHT_CP_ACCESS_KEY=//p' "${HINDSIGHT_INSTALL_ROOT:-$HOME/.local/share}/astrbot-memory-<id>/.env" | tr -d '\047\042'
```

默认路径为 `~/.local/share/astrbot-memory-<id>/.env`；自定义过安装目录时，按安装输出替换命令中的路径。在插件页 **查看和管理记忆** 右上角点击问号，也能找到带服务编号的读取命令。将输出的密钥填入官方网页登录框；连接已有服务时，向维护者获取网页登录密钥。

在 **运行管理 → 用户记忆 → 查看和管理记忆** 中复制官方管理地址和记忆库编号，登录后找到对应 Bank，即可浏览、搜索、更正、删除、导入和导出。Bank 是每个用户的记忆库，首次保存聊天时由插件自动创建，无需在官方页面另建。

浏览、搜索和导出无需维护。修改、删除或导入前，先按 [使用指南](USAGE.md#官方内容维护) 开始维护，等页面显示“可以修改记忆”后再操作，完成后结束维护。

## 三、选择使用者并完成设置

1. 选择 QQ 机器人，填写发消息者自己的 QQ 号；多人使用时分别添加。
2. 点击 **完成设置**，即可在 **运行管理 → 用户记忆** 中选择用户，调整“正常记忆 / 只用已有记忆 / 暂停记忆”，之后正常聊天即可。

只有列表中添加的机器人与账号组合可以使用记忆。清空列表后，没有账号使用记忆。保存立即生效，页面转到运行管理；尚未聊天也可以选择用户和调整模式，但官方页面要等首次聊天保存、记忆库建成后才能查看该 Bank。机器人离线时会提示先连接机器人。

总开关使用 AstrBot 插件面板的启停；关闭插件后停止记录新内容、查询记忆和发送待保存记录，服务已经接受的任务仍可完成。

## 四、服务维护与卸载

配套服务的模型与重新部署入口位于设置，服务运行状态在“运行管理”查看。模型连接检查通过后直接保存生效，无需重新生成安装命令；更换嵌入模型、参数或维数需要迁移已有向量数据。

服务维护直接展开。卸载后安装入口仍可用，重新生成命令即可再次安装。

在 **设置 → 服务维护** 确认删除全部记忆数据后，可生成完整卸载命令，在原安装主机执行。这会删除这套服务中所有用户的记忆，无法恢复。命令按安装标识检查目录与资源，只删除这套配套服务的容器、专属网络、数据卷和安装文件。共享镜像、Docker、AstrBot 和其他服务不属于卸载范围。插件本体在 AstrBot 插件面板卸载。

已有 Hindsight 不提供服务卸载操作。

## 常见问题

### 找不到「记忆管理」视图

检查 AstrBot 版本是否为 4.29.1 或更高，插件是否安装成功并处于启用状态。更新插件后可先重载，再重新打开插件详情。

### 模型列表中没有嵌入模型

普通对话模型不能替代嵌入模型。到 AstrBot **模型供应商 → 嵌入** 添加模型，保存后返回插件，模型列表会自动更新。无需在插件里再次输入模型 Key。

### 模型验证或保存超时

模型验证与服务启动在后台处理，页面自动获取进度。暂时无法获取进度时会重新连接；处理失败会显示原因并提示重试。网络中断后重新打开页面，可以继续查看仍在执行的任务。重复提交同一个处理中请求不会再次启动服务。

### 供应商显示不兼容

支持的模型接口见 [模型兼容范围](SUPPORT.md#模型供应商复用)。模型类型未适配、使用多模态嵌入或请求参数冲突时，页面会显示具体原因。

### 安装命令提示无法使用 Docker

请在服务器主机的终端执行，不要在 AstrBot 容器内部执行。Docker Engine 和 Compose v2 需要安装完成，执行命令的账号需要有 Docker 使用权限。

### 安装时下载或构建失败

终端会显示 Docker 的具体错误。检查服务器到镜像仓库及软件源的网络后，重复执行同一条安装命令。重复执行沿用服务身份和数据库。

### 提示无法连接后端

配套安装需在运行这套 AstrBot 的 Docker 主机执行。已有服务请检查 API 地址、端口和网络是否可达；Docker 容器之间一般使用服务名称，而不是 `localhost`。

### 模型地址使用 localhost

配套记忆服务在独立容器中运行，不能直接复用指向 AstrBot 自身的 `localhost`、`127.0.0.1` 或 `::1`。请在 AstrBot 模型供应商中使用记忆容器也能访问的服务地址。Docker 中的模型可使用共享网络内的服务名称；仅监听宿主机回环地址的模型，需要先调整监听地址和容器网络。

### 提示 API Key 无效或后端未启用认证

配套安装的 Key 自动交接。连接已有服务时，使用服务 API Key，并请维护者确认已启用认证。服务 Key 与 Hindsight 网页登录 Key 不同。

### 提示执行器不支持

在所选 QQ 用户使用的 AstrBot **配置文件 → AI → Agent 执行方式**中选择 **内置 Agent**。Dify、Coze 等执行器没有接入自动记忆流程。

### 保存后还看不到记忆

账号从启用后的新消息开始记录，首次保存时自动创建记忆库，无需在官方页面另建。后台需要整理时间；可以在 **运行管理 → 用户记忆 → 记忆保存与维护** 查看保存进度和错误，再用记忆库编号在官方页面找到对应 Bank。群聊、媒体和命令不自动记录。保存使用者后就能选择用户和设置模式，记忆为空也能操作。

### 导出 JSON 文件失败

管理员可在官方 Control Plane 使用原生导出，无需经 QQ 传输。

使用私聊 `/hindsight export` 时，AstrBot 与 OneBot 分容器可能需要配置文件回调地址。在 AstrBot **系统配置**填写 OneBot 能访问的 `callback_api_base`，例如同网络的 `http://astrbot:6185`，或由维护者设置共享文件目录。

### 提示需要恢复控制目录

按 [备份与恢复](DATA-MAINTENANCE.md#异常提示) 恢复匹配的控制目录。

### 提示 Bank 丢失、维护中或历史更正需交接

`bank_missing` 表示已经建好的记忆库丢失，`/hindsight on` 不会重建。恢复原 Bank 后，在插件页点击 **结束维护并恢复**；决定舍弃旧记忆时，点击 **清空此用户的记忆**，清理后再开启“正常记忆”。清空无法恢复，AstrBot 聊天记录不删除。维护、任务结果不明和历史更正的处理步骤见 [异常提示](DATA-MAINTENANCE.md#异常提示)。

## 高级配置

队列、召回预算和维护参数仍可在插件标准配置中调整。批量部署可参考 [配置示例](../examples/config.example.json)，数据搬迁见 [数据维护](DATA-MAINTENANCE.md)。
