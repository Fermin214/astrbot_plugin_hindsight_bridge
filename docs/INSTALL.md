# 在 AstrBot 中安装与配置

本指南适用于已经能通过 OneBot v11 与 AstrBot 正常私聊的 Linux 用户。AstrBot 使用 **4.29.1** 和内置 Agent。Windows 部署支持安排在后续版本。

## 一、安装插件

打开 AstrBot **插件管理 → 安装 → 从链接安装**，粘贴：

```text
https://github.com/Fermin214/astrbot_plugin_hindsight_bridge
```

依赖会自动安装。完成后打开 **Hindsight Memory 插件详情 → 记忆管理**，选择 **首次设置**。

## 二、连接记忆服务

### 第一次使用

选择「安装配套记忆服务」：

1. 选择 **对话模型**，供 Hindsight 整理记忆使用。
2. 选择 **嵌入模型**，供 Hindsight 查找相关记忆使用。
3. 重排模型可以不选，使用默认排序。
4. 点击 **生成安装命令**，复制完整命令。
5. 在运行这套 AstrBot 的 **Linux 主机终端**粘贴并执行一次。该主机需已安装 Docker Engine 和 Compose v2，终端账号需能使用 Docker。
6. 等终端显示「安装完成」，回到 AstrBot 的首次设置页面。

模型列表来自 AstrBot 已配置的供应商，无需重复填写地址和 Key。模型类型不兼容时，列表会说明原因。缺少嵌入模型，可先到 AstrBot **模型供应商 → 嵌入** 添加，再回向导刷新状态。

安装器自动准备数据库、Hindsight **1.1.0**、服务 Key、稳定身份和网络，并从记忆服务中检查模型连接。服务文件保存在执行命令者的 `~/.local/share/astrbot-memory-服务编号/`，安装结束会显示准确位置。AstrBot 使用 Docker 时，安装器复用它的桥接网络并保存网络配置；API 不额外开放主机端口。

命令包含生成服务所需的连接信息，只在自己的服务器终端使用。模型调用沿用所选供应商的计费规则。

### 已有记忆服务

选择「连接已有 Hindsight」，填写：

| 项目 | 填写方式 |
| --- | --- |
| API 地址 | AstrBot 能访问的 Hindsight 1.1.0 API 地址，例如 `http://hindsight:8888` |
| API Key | 服务 API Key，由维护者提供；不是模型 Key 或网页登录 Key |

点击「检查连接」。已有服务的模型配置由该服务维护，不会被插件覆盖。手工部署步骤见 [Linux 部署说明](../deploy/README.md)。

改连另一套服务会使用独立记忆，旧记忆保存在原服务。恢复原地址会沿用原来的记忆身份；同一服务搬迁地址按 [数据搬迁步骤](DATA-MAINTENANCE.md) 操作。

后端 `9999` 是 Hindsight 自带管理网页，插件连接的是 `8888` API。AstrBot 在 Docker 中时，`127.0.0.1` 指向 AstrBot 容器自身；已有服务需要提供同网络容器地址或其他可达地址。

## 三、选择使用者并启用

1. 在账号列表中选择 QQ 机器人对应的 **接入实例**。
2. 填写发消息者自己的 **QQ 号**，多人使用时分别添加。
3. 选择时区：中国大陆使用 `Asia/Shanghai`，香港使用 `Asia/Hong_Kong`。
4. 点击 **连接并启用**。

列表只开放明确添加的实例与账号组合，留空不能启用。稳定服务标识和控制目录由插件处理，无需手动填写。

保存时，插件检查连接并使配置生效，无需再重载。所选账号使用的对话配置会关闭「现实世界时间感知」和「用户识别」，避免消息附加文字影响原文关联；这些设置若由多个账号共用，变更会作用于同一配置文件。

之后正常聊天即可。管理页面见 [使用指南](USAGE.md)。

## 常见问题

### 找不到「记忆管理」视图

检查 AstrBot 版本是否为 4.29.1，插件是否安装成功并处于启用状态。更新插件后可先重载，再重新打开插件详情。

### 模型列表中没有嵌入模型

普通对话模型不能替代嵌入模型。到 AstrBot **模型供应商 → 嵌入** 添加模型，保存后返回插件点击「刷新状态」。无需在插件里再次输入模型 Key。

### 供应商显示不兼容

向导支持 OpenAI Chat、Responses、Claude、Gemini，以及百炼和 Ollama 原生嵌入。常用代理、请求头和额外参数可以沿用。模型类型未知、使用多模态嵌入或请求参数覆盖记忆处理所需字段时，会显示具体原因，见 [模型兼容范围](SUPPORT.md#模型供应商复用)。

### 安装命令提示无法使用 Docker

请在服务器主机的终端执行，不要在 AstrBot 容器内部执行。Docker Engine 和 Compose v2 需要安装完成，执行命令的账号需要有 Docker 使用权限。

### 安装时下载或构建失败

终端会显示 Docker 的具体错误。检查服务器到镜像仓库及软件源的网络后，重复执行同一条安装命令。重复执行沿用服务身份和数据库。

### 提示无法连接后端

配套安装需在运行这套 AstrBot 的 Docker 主机执行。已有服务请检查 API 地址、端口和网络是否可达；Docker 容器之间一般使用服务名称，而不是 `localhost`。

### 模型地址使用 localhost

配套记忆服务在独立容器中运行，不能直接复用指向 AstrBot 自身的 `localhost`、`127.0.0.1` 或 `::1`。请在 AstrBot 模型供应商中使用记忆容器也能访问的服务地址。Docker 中的模型可使用共享网络内的服务名称；仅监听宿主机回环地址的模型，需要先调整监听地址和容器网络。

### 提示 API Key 无效或后端未启用认证

配套安装的 Key 自动交接。连接已有服务时，使用服务 API Key，并请维护者确认已启用认证。服务 Key 与 Hindsight 网页登录 Key 不同。

### 提示执行器不支持

在所选 QQ 用户使用的 AstrBot **配置文件 → AI → Agent 执行方式**中选择 **内置 Agent**。Dify、Coze 等执行器没有接入自动记忆流程。

### 保存后还看不到记忆

账号从启用后的新消息开始记录。后台需要整理时间，列表不会立即更新；可以到「运行状态」看待办和错误。群聊、媒体和命令不自动记录。

### 导出 JSON 文件失败

管理员可直接在插件管理视图下载 JSON，无需经 QQ 传输。

使用私聊 `/hindsight export` 时，AstrBot 与 OneBot 分容器可能需要配置文件回调地址。在 AstrBot **系统配置**填写 OneBot 能访问的 `callback_api_base`，例如同网络的 `http://astrbot:6185`，或由维护者设置共享文件目录。

### 提示需要恢复控制目录

按 [备份与恢复](DATA-MAINTENANCE.md#异常提示) 恢复匹配的控制目录。

## 高级配置

队列、召回预算和维护参数仍可在插件标准配置中调整。批量部署可参考 [配置示例](../examples/config.example.json)，数据搬迁见 [数据维护](DATA-MAINTENANCE.md)。
