# 安装与连接

运行环境要求：AstrBot **4.29.1 及以上**（使用内置执行器 `local`）以及 Hindsight **1.1.0 或 1.2.0**。

各平台接入方式见对应文档：[微信 ClawBot](WEIXIN.md)、[Telegram](TELEGRAM.md)、[飞书](FEISHU.md)。Linux 下只要装有 Docker Engine 和 Compose v2 即可使用配套安装；Windows 需自行启动或连接已有 Hindsight，具体步骤见 [Windows 原生部署](WINDOWS.md)。完整支持列表见 [兼容范围](SUPPORT.md)。

## 一、安装插件

在 AstrBot 的 **插件管理 → 安装 → 从链接安装** 中填入仓库地址：

```text
https://github.com/Fermin214/astrbot_plugin_hindsight_bridge
```

安装完成后，打开 **Hindsight Bridge 插件详情 → 记忆管理 → 插件设置**（**插件设置** 管理连接、模型和参数，**用户与记忆** 用于添加账号与配置聊天记忆）。

## 二、安装或连接记忆服务

切换连接方式后，需要点击对应区域的 **保存连接** 或 **保存并连接** 才会生效。

### 安装配套服务

1. 在 **Hindsight 服务连接** 选择 **安装配套服务**，点击 **生成安装命令**。
2. 复制命令，在运行 AstrBot 的 Linux 主机终端里执行。
3. 命令执行完后回到页面，在 **配套服务模型** 中选择记忆处理模型与向量模型（重排模型可选），点击 **保存并连接**。页面会验证模型、启动服务并完成接入。

安装器会在同一台主机部署数据库、Hindsight **1.2.0** 和官方 Control Plane，并自动配好服务连接密钥。

- **网络自适应**：插件会自动识别 AstrBot 的运行方式（自定义 bridge 用容器名、默认 bridge 用网桥网关端口、host 或原生运行用本机回环端口）。
- **页面管理地址**：配套模式下 API 地址为只读，如需记录浏览器访问地址，填写 **Hindsight 管理地址** 后点击 **保存管理地址** 即可，不会重启服务。
- **同版维护与升级**：如需更新 1.2.0 配套组件或数据库扩展，在 **配套服务运维** 点击 **重新部署**，原有配置和记忆会保留。如果之前装的是 1.1.0，通过顶部升级提示进入升级流程，详见 [服务升级步骤](DATA-MAINTENANCE.md#升级-hindsight-服务)（插件不会强行自动升级旧版 Hindsight）。
- **安装中断重试**：如果在选模型前中断，重新执行同一条安装命令即可，已有身份、凭据和数据卷都会保留。

### 连接已有 Hindsight

选择 **连接已有服务**，填写服务 API 地址与 API 密钥，点击 **测试连接**，验证通过后点击 **保存连接**。

接入后可直接使用全部用户管理和记忆功能；服务本身的模型、升级和备份由你原有部署自行维护。

- **常用端口**：API 默认端口通常为 `8888`，Control Plane 网页端口通常为 `9999`。注意如果 AstrBot 跑在 Docker 桥接网络里，容器内的 `127.0.0.1` 指容器自己，应改填宿主机或同网络服务地址。
- **管理地址**：**Hindsight 管理地址** 填写管理员浏览器能打开的 Control Plane 地址，具体手工部署方式见 [Linux 部署说明](../deploy/README.md)。

### 独立访问官方 Control Plane

Hindsight 官方网页面板与插件页面分开登录。远程服务器上运行的官方面板默认只监听本机回环地址，可通过独立域名反向代理或 SSH 隧道访问：

- **有域名**：为 `127.0.0.1:9999` 配一个独立的 HTTPS 域名（如 `https://memory.example.com`）。
- **无域名**：在自己的电脑终端运行 SSH 端口转发并保持开启：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:9999:127.0.0.1:9999 your-user@your-server
```

将 **Hindsight 管理地址** 设为 `http://127.0.0.1:9999`（改过端口则同步调整；Nginx/Caddy 反向代理示例见 [部署说明](../deploy/README.md#五打开官方-control-plane)）。

配套部署的网页登录密钥保存在服务器安装目录的 `.env` 中，执行以下命令即可查看（把 `<id>` 换成安装输出里的服务编号；自定义过 `HINDSIGHT_INSTALL_ROOT` 时对应调整路径）：

```bash
sed -n 's/^HINDSIGHT_CP_ACCESS_KEY=//p' "${HINDSIGHT_INSTALL_ROOT:-$HOME/.local/share}/astrbot-memory-<id>/.env" | tr -d '\047\042'
```

连接已有服务时，请向该服务的管理员索取登录密钥。

打开官方面板后，在 **用户与记忆** 顶部复制用户的 **Bank ID** 即可查找对应记忆库（Bank 会在首次保存聊天时自动建立，不需要提前在官方页面手动创建）。日常修改、删除单条记忆直接在 Control Plane 操作即可；要彻底清空整个用户的记忆库，请用插件面板的 **清空记忆**，详见 [使用指南](USAGE.md#在官方面板修改记忆)。

## 三、添加用户

1. 先在 AstrBot 配好并连上 QQ、微信 ClawBot、Telegram 或飞书机器人。
2. 进入插件 **用户与记忆**，点击 **+ 添加用户** 并选择平台实例：OneBot 填用户的 QQ 号；其余平台让测试用户私聊机器人发 `/sid`，填入返回的 UID。
3. 核对弹出的机器人账号，点击 **确认开通**。如果此时机器人恰好离线，用户会先保存进列表，等连上后再回用户页点击 **确认机器人身份**。
4. 在顶部的 **记忆模式** 切换为 **读写记忆**，直接聊天即可。

每个平台实例、机器人和用户的组合都对应独立的记忆，只有确认身份之后发送的消息才会被记录。点击 **移除用户** 会立刻停止该账号的记忆存取并移出列表，但已有记忆仍保留在数据库里，日后重新添加并确认身份还能继续使用。

如果需要整体暂停插件，直接在 AstrBot 的插件管理停用本插件即可；停用后不再采集或召回，Hindsight 已经收下的后台任务会继续处理完。

### QQ 官方机器人接入说明

在 AstrBot 填好 AppID、AppSecret 并开启 C2C 私聊事件。使用 Webhook 时，还需在 QQ 开放平台配置好指向 AstrBot 的公网 HTTPS 回调地址并完成订阅。

配置插件时，私聊发送 `/sid`，把返回的 Bot ID 作为平台实例 ID、UID 作为用户 OpenID（去掉外侧括号，保留原大小写；可参考 [官方机器人配置示例](../examples/config.qq-official.example.json)）。只要实例、AppID 和用户 OpenID 不变，在 WebSocket 与 Webhook 之间切换不会丢失原有记忆。更换 AppID 或实例后需要重新确认身份，新账号会启用新的记忆库。

## 四、配套服务维护

配套服务的模型变更、版本检查、升级、重装和卸载都在 **插件设置 → Hindsight 服务连接** 完成：

- **切换模型**：更换嵌入模型或向量维数前需留意 Hindsight 中的旧向量兼容性；同一套模型配置如果已验证就绪，重复点击 **保存并连接** 不会重复重启。
- **版本升级**：有新版本可用时页面顶部会出现升级横幅，点击 **查看升级** 按步骤执行即可；暂不升级可点 **忽略**（未结束的升级流程不能忽略）。
- **备份与卸载**：**配套服务运维** 中的 **备份** 可打开操作指引与可复制的备份脚本；点击 **卸载** 并勾选确认后会生成卸载命令，在原主机执行即可删掉配套容器、专用网络、数据卷和安装目录。

连接已有 Hindsight 时，插件页面不提供服务运维入口，两种模式的功能对照见 [README](../README.md#安装)。

## 常见问题

### 找不到「记忆管理」入口

确认 AstrBot 版本在 4.29.1 或以上，且插件处于启用状态；刚更新完插件时先重载一次插件再刷新页面。

### 模型列表里找不到向量（嵌入）模型

先到 AstrBot 的 **模型供应商 → 嵌入** 添加一个 Embedding 模型，保存后切回插件设置页列表会自动更新。

### 保存模型时验证或连接超时

模型探测、启动和接入在后台异步进行，页面会实时显示进度。如果不小心刷新或重载了插件，重新打开设置页会自动续接结果；若提示配置失败，按提示改完供应商设置后再点 **保存并连接**。

### 供应商显示不兼容

各家协议的支持范围见 [模型供应商复用](SUPPORT.md#模型供应商复用)。使用了多模态嵌入或带冲突参数时，下拉列表会直接标明不支持的原因。

### 执行安装命令提示找不到 Docker

安装命令需要在运行 AstrBot 的 **Linux 宿主机终端** 执行，不要进到 AstrBot 容器内部执行，且当前用户需要有 Docker 权限并已安装 Compose v2。

### 安装时拉取镜像或构建失败

检查宿主机到镜像仓库及软件源的网络连通性后，直接重新执行同一条安装命令即可，已有凭据和数据库卷不会丢失。

### 提示无法连接后端

确认容器网络与地址可达：配套部署务必跑在 AstrBot 同一台主机上；连接已有服务时，注意 Docker 容器之间一般填写服务名（如 `http://hindsight:8888`），不要在容器里填 `127.0.0.1`。

### 记忆检索超时

「检索最长等待」默认为 10 秒（可调范围 0.2–30 秒）。如果模型或向量服务响应偏慢，可以在 **插件设置 → 全局记忆参数** 调大这个值。超时后只会跳过该次召回，不影响正常回复和后台保存。

### 提示模型地址不能用 localhost

因为配套 Hindsight 跑在独立容器里，容器里的 `localhost` / `127.0.0.1` 指向它自己而不是宿主机的本地模型。请改填容器能访问的地址（如同一 Docker 网络的服务名，或开放局域网/网桥监听地址）。

### 提示 API Key 无效或后端未开启认证

配套安装的密钥由插件自动交接；连接已有服务时，请填写服务端的 API Key，并确认 Hindsight 已开启 API Key 认证（注意它与 Control Plane 的网页登录密钥不是同一个）。

### 提示执行器不支持

记忆流程目前只接入 AstrBot 的 **内置 Agent**（可在 AstrBot **配置文件 → AI → Agent 执行方式** 确认），Dify、Coze 等外部执行器暂不支持。

### 发消息后在面板还看不到保存的记忆

账号刚开通时，需要等第一条普通私聊发送后才会在 Hindsight 中新建 Bank，后台提取和入库也需要数秒到十几秒。可在 **用户与记忆** 顶部卡片查看「待保存 / 已保存」计数，再用 Bank ID 去官方面板查看结果。

### 导出记忆与复制交付记录

完整记忆通过 Hindsight Control Plane 导出。插件面板「使用记录」提供「参考内容」「发给 AI 的原文」「原始 JSON」三个页签，可复制交付原文与 JSON。

### 官方机器人没有回复

检查 AstrBot 日志中的登录状态、C2C 消息接收与发送日志；遇到 Token 过期或断连时，在 AstrBot 重载对应机器人实例即可。

### 浏览器打开 Webhook 地址提示 Method Not Allowed

Webhook 接口只接收 `POST` 请求，浏览器直接访问（`GET`）返回 405 是正常现象。在 QQ 开放平台完成回调验证后发一条私聊测试即可。

### 提示迁移来源不完整或记忆库丢失

参见 [异常提示](DATA-MAINTENANCE.md#异常提示) 对照错误码处理；如果是已建立的记忆库（`bank_missing`）被人为删掉，需要先恢复原 Bank 并点击 **核对记忆库**，或通过 **清空记忆** 重新建库。

## 高级配置

如需调整 token 上限、超时、分词编码、本地队列容量或额外的命令排除前缀，可在 **插件设置 → 全局记忆参数** 修改，保存后立即生效，无需重载。需要参考标准化配置模板可查看 [配置示例](../examples/config.example.json)。
