# 开发复盘 · 0.1.0–0.3.8

## 反复踩坑的六类原因

| 典型问题与案例 | 旧测试为什么没拦住 | 改进后的检查方式 |
| --- | --- | --- |
| **先做了功能入口，后来才发现越界。** 早期的自建记忆管理交还给了官方面板（`708a543`），为已有服务加的升级提醒后来也全部撤回（`34b8b58`）。 | 单测只看单个按钮能不能跑通，两套部署下表现一致，看不出是否管了不该管的服务。 | 设计每个写操作前先列清资源所有权；配套部署和已有服务各自走独立入口验收。 |
| **用发起时的状态决定结束时的写入。** 清空重试复用旧结果（`dc237ec`）、迟到的鉴权和知识页反馈覆盖新状态（`faa2d03`、`129aada`）、遗忘前的消息读到新代次提示（`7d07f4a`）。 | 常规顺序测试中，请求开始和结束时账号、连接和代次都没变，竞态完全不触发。 | 人为卡住请求，在途中切换账号、更换连接或执行清空，再放行旧请求核对最终写入与展示。 |
| **误把宿主局部事件当成主助手的最终交付。** 按事件挂载工具先后修过两次（`dd04d82`、`a198944`），子 Agent 抢先结束导致漏存主回复（`ef48ea1`），工具超额时漏记最后返回（`cd71e17`）。 | 钩子成功触发不代表就是当前主对话轮次，也不代表主模型真的收到了结果。 | 在真实宿主里构造子 Agent 抢先结束的场景，逐一比对主请求、持久历史和留存快照。 |
| **Mock 环境漏掉了真实宿主的后半段。** iframe 外链打不开（`27bd922`）、空卷因 SQL 权限装不上（`ecf10fc`）、页面轮询冲掉草稿（`d0b8da7`）、Windows 文件句柄占用导致备份归档失败（`44fd257`）。 | 截图、复用旧卷、纯 Linux 测试分别绕开了宿主容器限制、首次初始化和 Windows 文件锁语义。 | 必须在原生宿主面板里实际编辑保存；安装测空卷；备份归档在目标操作系统实地替换读回。 |
| **同一套规则在不同分支里写了两遍。** 单页与多页知识页预算到 `40b7153` 才合并；平台换号撤权与同账号换协议/重连保权反复修正（`b023816`、`8899dcc`、`a21dfbd`、`39f8a91`）。 | 正常样本下两条路径都能过，差异只出现在刚好踩线或切换协议的边界上。 | 共用逻辑收口；测试专门取“刚好装满”和“首个超额”样本，以及“真换号 / 短断线 / 换协议”对照。 |
| **把中间信号当成最终交付通过。** #5 修了管线吞错误和假绿报告，#18 修复只按最后一次推送算 CI 范围，#19 功能过测后漏升版本号。 | 进程退出码、部分用例通过或只看末次 push 都不足以代表整份 PR 交付完整。 | 按整份 PR 的 diff 选测；验收脚本检查清单与产物摘要匹配；打包脚本强校验版本号与基线对比。 |

## 0.3.8 的集中返工复盘

[PR #22](https://github.com/Fermin214/astrbot_plugin_hindsight_bridge/pull/22) 新增了按用户预算/助手开关、跳过诊断和配套报错细分，审查后又经历两轮集中修正（`02f7b09`、`d333eef`）及数据库修复（`0a3fbdd → d2754ba`）：

| 返工问题 | 根因分析 | 补齐的检查 |
| --- | --- | --- |
| **关闭“保存助手回复”后，旧回复依然挤占新材料。** 首修放在裁剪后过滤，长旧回复已把用户语境挤掉；二修改为先过滤再裁剪。 | 测单次开关没问题，但漏掉了「有历史记录 → 改设置 → 发新消息」的组合状态。 | 用足以挤掉用户历史的长旧回复作边界样本，直接检查最终发出的 Retain 原文。 |
| **最近跳过诊断窜号 + 命令匹配漏网。** 旧机器人迟到的拒绝事件覆盖了新身份诊断；`/hindsight status` 对自定义前缀和尾随参数识别不一致。 | 诊断状态写入时绕过了业务写入的身份约束，命令解析未对齐宿主规则。 | 身份切换测试同步验证拒绝分支；命令测试传入宿主完整格式并比对查询前后诊断不变。 |
| **QQ 特殊引用载荷与安装失败提示模糊。** 仅通过 `msg_elements` 带引用时识别不全；服务启动失败只报了阶段名，看不出具体卡在哪。 | 验收只用了常见载荷格式，未按具体错误码核对文案是否指明了排查动作。 | 用适配器契约覆盖替代载荷与时间异常，并在文案层核对错误是否指向明确操作。 |
| **pgvector 0.8.6 下架导致全新安装失败。** 老机器有本地缓存没暴露；后来因 0.8.6 安全公告撤回临时归档镜像，改用常规源 `>=0.8.7` 并补旧卷升级路径。 | 复用本地镜像测不出冷构建问题，只换新镜像又覆盖不了已有数据卷里的旧扩展版本。 | 新增每周 `managed-install` 冷构建巡检；修改镜像时强验证“无缓存新装 + 带旧数据卷升级”两条路径。 |
| **Windows 调度抖动与版本反复同步。** 一条超时用例混入了 300ms 调度耗时；功能原拟发 0.4.0 后改为 0.3.8，造成标题和变更记录多次改写。 | 业务超时断言依赖机器实时调度，版本号与说明在收尾阶段才介入。 | 超时测试改为直接注入超时，不赌时间窗口；初次整理 PR 时即对齐版本意图与用户文案。 |

回头看，绝大多数返工都集中在**两个状态交界的地方**：单测和正常链路各自都能绿，一旦跨过“换号前后”“设置修改前后”“离线冷构建 vs 旧卷复用”“宿主异步与插件状态”这些边界，隐藏假设就会暴露。后续优先自动化验证的正是这些交叉点，而不是堆砌同类正常用例。
