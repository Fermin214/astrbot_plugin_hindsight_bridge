# 插件实现说明

本文供贡献者了解插件的接口、身份与数据结构。安装与日常使用分别见 [安装指南](INSTALL.md) 和 [使用指南](USAGE.md)。

## 模块分工

AstrBot 负责接收消息、管理会话、调用聊天模型与发送回复。Hindsight 负责记忆提取（Retain）、记忆召回（Recall）、整合（Consolidation）、知识页生成与内容管理。插件负责消息来源校验、用户隔离、材料构造、持久队列、临时注入、连接及暂停与恢复协调。

支持 Linux、AstrBot 4.29.1 及以上版本的内置执行器 `local`、Hindsight 1.1.0 / 1.2.0，以及 OneBot v11（`aiocqhttp`）和 QQ 官方 WS/Webhook 的 C2C 私聊纯文字，默认同机部署。完整兼容范围见 [兼容范围](SUPPORT.md)。

插件只调用 Hindsight 的公开 HTTP API，不把 Hindsight 安装进 AstrBot 的 Python 环境，也不额外调用摘要模型；自动 reflect 关闭。

面板的 `parameters/save` 只保存插件记忆参数，与标准配置共用 `AstrBotConfig`。保存须携带完整配置修订，校验数值范围、前缀列表与分词编码，加载编码后再次核对修订；成功持久化后直接更新客户端分词编码和队列容量，其余参数由后续请求读取。连接、身份、Bank、代次、账号确认、记忆模式和维护暂停均不随参数保存改变，已有队列与冻结材料持续使用原实例。页面分别显示保存值与运行值，轮询保留草稿，修订冲突要求重新加载。

## 用户与账号

账号权限按平台实例 ID 与用户 ID 的精确组合检查。每个稳定逻辑用户使用独立 Bank，会话变化不改变长期归属。`agent_id`、`service_id`、部署 ID 和账号映射参与连续身份管理。

`service_address_revision` 用于同一服务迁址；换成另一套服务则使用新的 `service_id`。旧队列不会直接转发到另一套服务。

账号配置只接受 `allowed_accounts` 中明确填写的平台实例与用户组合，空列表关闭所有账号的记忆访问。插件启停由 AstrBot 生命周期管理。

来源头与自动采集共用原始载荷校验。OneBot 原始 `self_id` 证明接收账号，事件携带的客户端须属于当前宿主实例；只读登录检查在异步准备和上传边界执行。未知平台仍拒绝访问。QQ 官方两种传输共用逻辑平台类型 `qq_official`，宿主类型分开核对；身份包含部署、实例、AppID 和原始 OpenID，不同实例始终隔离。

`core/qq_source.py` 只读取 AstrBot 原生 adapter/client 的认证身份。WS 核对 SDK robot，Webhook 核对已认证 helper/user 及 client/API/HTTP 对应；登录快照冻结对象引用和认证 ID。消息携带的 client 和原始 API 必须属于该登录，重载或登录变化后拒绝旧产生方事件。插件不保存 AppSecret、不实现签名服务器或 QQ 客户端。

独立控制库中的授权修订绑定平台实例、用户与真实来源身份。新增和再授权须由 Dashboard 管理员显式确认；授权时间下限单调推进，配置恢复不能重启撤权。旧 OneBot 身份、Bank、采集下限和冻结请求保留。状态变更命令使用可信原始时间与持久事件凭据，控制变更和消费记录通过同一 SQLite 事务提交；跨异步前先核对边界，提交后再重放到业务库。

身份层保存 `principal_id` 和 Bank 归属。每个稳定用户范围使用独立 Bank，记忆空间固定为 `default`。不提供跨账号绑定、账号转移或历史 Bank 合并。

## 用户消息与助手正文

用户原文须通过标准接收事件、原始载荷与模型请求的关联核对。接受 OneBot v11 私聊纯文本及已验证的 QQ 官方 C2C 纯文本；history 中的 user 文本不能替代接收入站校验。官方 C2C 核对原始 author.user_openid/id/content/timestamp、纯文字消息类型及已验证的合成 At/Plain 组件，拒绝引用、附件、未知扩展和不一致的正文转换。原始时间须带时区，用户材料标为 `qq_official.timestamp`，不回填宿主时间。AstrBot 追加的时间、身份与群名提示按独立 `system_reminder` 内容块识别；首块仍须与入站原文完全一致，其他附加内容或轮次不匹配时拒绝关联。原始正文和持久历史都不改写。

助手正文读取自标准 `conversation_manager` 的持久化 `history`，并关联同一来源账号、代次和会话中已核对的用户事件。每条最终正文保存后独立入队，无需下一条用户消息触发。

`history_baselines` 保存前置历史长度与前缀摘要，`task_id` 关联用户窗口任务。只有前置读取成功、后续历史增长、原前缀不变且新增部分含对应用户轮次和最终助手正文时，才建立助手记录。前置读取失败时用户原文仍可独立采集；历史压缩、编辑或截断改变边界时拒绝关联，不按相同文本猜配旧历史。

助手材料使用 `role=assistant`、`delivery=unknown`、`time_source=history_observed_at`。时间取首次观察到持久化正文的时刻，并在重试时沿用。发送回执作为可选附加信息。

| AstrBot 4.29.1 发送路径 | 接口行为与限制 |
| --- | --- |
| 普通回复 | 发送异常被阶段捕获后仍触发 `after_message_sent`，钩子不提供底层成功消息 ID |
| 分段回复 | 后钩子含完整待发送结果，没有逐段成功状态和出站 ID；部分失败时仍含失败片段 |
| 流式回复 | 发送阶段提前返回，没有发送后钩子；完成事件只表示生成结束 |
| 调用方直接发送 | OneBot API 可返回调用方的消息 ID，旁观插件无法取得其他调用的返回值；直接发送不能替代标准 history 来源 |

各路径均以最终持久化正文及有效来源关联为采集依据。排除 system/tool/reasoning、工具调用中间消息、临时召回块、压缩摘要与未保存草稿；工具调用后的最终助手纯文本仍按相同规则采集。

## 材料与队列

用户文档沿用 `uw1` 身份，助手正文使用独立 `aw1` 文档和 operation UUID。新建双方材料为 `dialogue_window_v2`，单条新增正文最多 8,000 字符。

语境窗口限同一账号、代次和会话最近 30 分钟内最多 4 个已核对用户轮次及对应助手，历史正文合计最多 4,000 字符，超限按最旧完整轮次移除。窗口帮助解释“第二个”等指代。旧 `uw1` 冻结请求不补入后来的助手正文。

提交前原子保存身份、正文、摘要和操作 UUID。用户任务在限时召回结束后放行，助手任务独立放行。重试沿用原操作和冻结材料，明确失败通过 Operations retry 处理。

未完成队列默认最多 10,000 条、请求正文最多 64 MiB。完成任务清除队列正文，保留去重和操作信息。后端操作历史持续保留，供接受确认和恢复核对。

页面的已保存计数复用完成任务行，仅统计所选服务、owner、Bank 和代次中 `state='done'` 的材料。用户消息和助手最终正文各计一条，语境引用与操作子任务不额外计数；取消、放弃及清空后的旧代次不计入，不增加统计表或远端扫描。

## 召回与官方内容

召回范围限同一用户 Bank，只临时注入模型请求，不改写人格和持久聊天历史。自动检索默认等待 10 秒，`recall_timeout` 可设为 0.2 到 30 秒，覆盖查询构造、认证与检索；上下文最多 4,000 字符。无匹配、检索超时和连接失败分别附带简短本轮状态，普通聊天继续。成功时说明相关记忆由插件自动检索，并附带官方返回的结构化记忆。

初始化检查连接配置缺项和召回超时范围，不为已有数据自动替换服务标识。启动后后台检查连接与认证，失败后重试；该检查不阻止本地队列采集。HTTP 连接、读写、连接池等待、认证和会话读取超时分别诊断。告警按错误码节流并累计次数；每个用户的最近检索结果、耗时和连续失败次数与服务连接状态分开显示，诊断不保存聊天正文。

数据恢复检查先于上传连接恢复；只存在认证暂停时，本地恢复完成后可继续采集，远程提交仍暂停。需要核对已接受任务或执行旧记忆清理时，原有恢复闸门继续生效。

`memory_block(results, limit=...)` 格式化官方返回的记忆，按上下文上限生成临时注入块。事实更正、失效、删除与重处理使用官方 Control Plane 和公开 API。

QQ 的 view、show、export 保留本人范围检查，作为官方只读 API 的薄入口，不叠加本地内容覆盖。`correct` 旧命令仅引导管理员使用官方 Control Plane，不创建 `uc1`、`ac1` 或其他本地更正任务。

个人导出包含官方世界事实（World Facts）、经历（Experience）、观察（Observations）和源文档。分页发生变化、超过数量或字节限制、来源缺失时返回明确错误，不将部分内容作为完整导出。

## 知识页（Knowledge Page）

`core/background.py` 在最新控制库的 `settings` 中保存 owner 的有序原生页/model ID、授权修订、Bank/代次、开关及单调选项修订，不保存正文。引用格式 2 保存最多 8 个去重映射，格式 1 按单元素列表读取且不触发写入；`page_id` / `mental_model_id` 兼容字段指向列表第一篇，空列表为空字符串。默认关闭，管理员通过 Dashboard API 从用户 Bank 的官方树和页接口确认映射；本人 `/hindsight background [序号]` 仅查看已选页，不创建、刷新或修改内容。个人导出格式不变，不包含知识页与版本历史。

自动读取使用单模型 `detail=content`，投影正文、刷新时间和失败时间；Hindsight 1.1.0 / 1.2.0 在该路径返回 `is_stale=null`，标记为新鲜度未知。树索引的 stale 作为独立时点的元数据展示，内容快照按模型读取核对，完整遗忘按官方资源删除检查确认。知识页响应在流式解码中限制为 256 KiB，目录最多 500 节点、12 层；未知结构和不匹配映射拒绝，读取以已确认原生 ID 为准。

知识页和 Recall 共用总 token/字符/等待预算。`background_max_tokens` 为含包装的独立页面上限，默认 400，范围 64–8192，不按共享预算比例缩减。共享 `recall_max_tokens` 默认 1200、范围 256–8192，`context_max_chars` 默认 4000、范围 256–32768。完整页放不下时全部跳过；记忆按既有顺序保留完整条目，最终上下文连同状态说明须符合两个共享上限。选页和已选页列表读取复用聊天包装计算长度，只返回计数与诊断，不存正文；长度检查不预判聊天的检索结果。目录 `index_stale` 单独显示，不用其推断正文快照新鲜度。

认证后知识页与 Recall 并发读取。所有页面共用 `background_timeout` 截止时间，默认 1 秒、范围 0.05–10 秒，且不超过剩余总等待预算四分之一；最多并发 4 篇，排队也计入子限时。按选择顺序尝试装入完整页，失败或超限后继续尝试后续页，再放入完整检索条目；最终正文与状态说明同时满足共享预算。逐页结果只保存 ID、状态码、使用标记及超出项，任何认证失败丢弃同轮全部内容。总等待仍受 `recall_timeout` 约束，取消后回收任务。页面预算与子限时参与读取守卫，配置或顺序改变后丢弃在途旧结果。未启用知识页时保留原召回路径，使用相同的共享长度上限。

读取前冻结当前 client/outbox、连接设置、权限、Bank/代次、模式和选项修订，返回后及注入前重新核对。临时内容不入持久 history 或冻结材料，用户采集仍在 finally 放行。关闭、撤权、暂停保存和查询、遗忘、换连接或资源关闭使晚到结果失效。完整遗忘清除选页引用并保留修订墓碑，新 Bank 默认关闭；后台刷新和来源更正沿用既有 Bank 协调。

多页选择保存先并发读取原生页，再并发读取对应模型；每项 I/O 前后执行同步守卫，阶段之间核对机器人原生身份，身份查询次数不随页数增长。保留的已确认映射即使页面被删除，也允许排序和逐个移除，长度检查明确报告缺失；新增页及变更的 model ID 仍须通过原生正文核对。

## 按需读取与 Agent 工具

`core/agent_tools.py` 通过公开 `Context.add_llm_tools` 注册本插件的读取与 Reflect `FunctionTool`，以模块和实例确认归属，已有同名项保持原归属。请求钩子只复制 `ToolSet` 并过滤所属条目，保留其他工具及宿主原有选择；不主动补入被宿主排除或停用的工具。普通入站事件、宿主上下文和插件实例共同确定读取范围，工具参数不含 Bank、用户、URL、凭据或任意过滤器。

读取方式在控制库 `settings` 的 `reading:` 键中按连接与 owner 保存，格式 1 包含模式、源身份、确认修订、Bank/代次及单调设置修订。默认自动召回，按需方式仅停止自动事实 Recall，原有采集与自动知识页独立。完整遗忘写入修订墓碑并恢复自动方式，旧配置不能恢复工具设置。面板保存核对完整配置、scope 和读取设置修订，并按最近实际请求确认的会话与模型重新检查可用性。

每条有效原始事件建立独立工具账本，跨续轮共用 4 次调用及累计 `2 * recall_max_tokens` / 16 KiB 输出额度；单次输出同时受 `recall_max_tokens`、`context_max_chars` 和 8 KiB 限制，含 JSON 包装。输出预留 32 token / 128 字节的拒绝提示空间；额度用完返回非空提示并移除该请求中的所属工具，避免宿主把空返回值当作结束聊天。读取最长 3 秒且不超过 `recall_timeout`，账本在主 Agent 完成时关闭，最长保留 120 秒。账本只保存身份与正文摘要、修订、模型指纹、计数、时间，以及请求和运行上下文的弱引用，不缓存查询、结果或页正文。并发调用由同一账本锁协调。

请求的临时记忆参考带有随机标识，计入共享背景预算；临时用户内容不进入持久会话或原始用户材料，最终助手正文仍原样保留。公开 `on_agent_begin` 钩子只有在实际运行上下文同时包含该请求的提问与临时标识时才绑定账本；独立 Agent 即使复用事件和主 Agent 钩子，也不能提前认领另一请求的额度或消耗最终助手采集记录。`on_agent_done` 关闭同一上下文的账本。每次调用前、原生读取返回后和交付前核对最新身份、模式、连接、Bank/代次、设置、实时请求模型与工具归属。显式供应商选择使用宿主公开接口解析。AstrBot 的公开上下文不提供回退后的执行供应商，因此存在回退配置时拒绝开放按需工具；自动召回保持原有语义。后台调用、缺少实际入站、跨运行上下文或子代理交接不开放读取。关闭插件只取消其自行创建的读取任务，并向宿主返回安全结果；宿主取消仍传播。旧实例、撤权、维护、清空和配置变化后的结果不能进入后续聊天。

原生 `skills_like` 轻量 schema 不保留 handler 归属。账本通过弱引用保存插件创建的请求工具副本，并结合该副本的所属实例、模型可见的轻量名称与描述核对能力。额度用完时同时移除可见轻量条目和该请求原始副本中的所属工具，不访问或修改宿主执行器的私有缓存，不改变全局工具集合或其他工具。

`core/reading.py` 使用原生搜索、树、页、模型正文、来源和历史 API，响应先在流式解码中限制为 256 KiB。长页按原文完整行返回位置，内容摘要与刷新时间共同绑定版本；续读缺少版本或内容变化时拒绝拼接。Recall 保留原生来源事实编号、文档/块编号、角色与时间，仅投影已知归因字段。来源缺失保持未知，历史数组整体受传输上限约束后才投影最近 5 条，失败记录不算内容版本，过长快照明确省略正文。

原生工具输出可由 AstrBot 持久保存到会话和日志，不使用自动参考的临时标记。Bridge 不修改宿主工具历史和日志；直接 tool 响应及 assistant tool_calls 不作为新材料，最终助手正文继续沿用原有采集和归因规则。完整遗忘范围限于 Bridge 和所属 Hindsight Bank，宿主会话及其工具副本保持由宿主管理。

## Reflect 与执行终点

`core/reflection.py` 保存连接和 owner 范围的 `reflect:` 设置，默认关闭，等待默认 12 秒、范围 3–30 秒。设置绑定源身份、确认修订、Bank/代次及独立修订。自动召回与按需方式均可开启 Reflect；每条原始消息最多一次，与其他读取共用调用和输出账本。单次回答受相同 token、字符和字节上限约束，原生请求使用 low budget 和受限 `max_tokens`，只接受查询参数。来源和用量从原生响应投影，未知字段与原始错误不交付。

控制库格式 6 的 `reflection_requests` 在 HTTP 发送前记录请求编号、连接、owner、Bank、代次、时间与状态，不保存查询、答案或凭据。`prepared` 到 `dispatched` 的变更与最后范围核对在同一事务内完成。清空操作先使旧范围失效；删除旧 Bank 前检查其未结束请求。维护就绪检查同样包含这些请求。

工具等待与 HTTP 任务寿命分开，传输任务最长 120 秒。工具超时后继续跟踪原生传输，完整成功响应或传输明确证明未发送时关闭屏障；晚到正文不回填聊天。不能确认执行终点时保留 `unknown`。实例关闭取消其所属任务，重载将遗留 `dispatched` 转为 `unknown`，未发送的 `prepared` 可以删除。

Hindsight 1.1.0 / 1.2.0 的 Reflect 可创建缺失 Bank，但没有公开的请求级执行终点接口。执行不明时不能靠查空 Bank、等待固定时长、审计日志或重复删除解除屏障。恢复其他用户的业务快照可与受屏障隔离的旧 Bank 清空分开进行，不把该清空标记为完成。旧插件拒绝格式 6，避免忽略屏障后删除 Bank。

## 暂停与 Bank 协调

保存和查询暂停状态按受影响 Bank 持久保存。暂停保存和查询后阻止新用户材料、助手回调采集、迟到召回注入、新提交和重试；已接受任务继续追踪并正常排空。未提交旧待办需要显式作废，不能在官方修改后重放。

解除读写暂停前核对任务结果、在途请求与 Bank 映射，清理过时的短期语境，再显式恢复。提交或取消结果尚未确认时保持暂停。决定舍弃旧记忆时，完整遗忘流程通过独立控制日志作废旧任务、登记新 Bank 代次并持续清理。

Hindsight 1.2.0 可能将被其他整合任务替代的操作记为 `cancelled`。恢复原模式前，通过同 Bank 单项公开接口复核：仅将类型为 `consolidation`、状态仍为 `cancelled`、带有效 `completed_at` 且没有子任务的记录视为已收尾；其余待处理、处理中或取消未确认的任务仍阻止恢复。普通协作取消没有完成标记，仍按在途处理；替代任务仍由全 Bank 操作扫描核对，不依赖内部 `result_metadata`。

首次保存记忆时自动创建 Bank。已经建立的 Bank 被官方删除后，停止读写并报告 `bank_missing`，禁止按首次建库路径自动重建。恢复原 Bank 后需显式核对记忆库；已有读写暂停时再解除；放弃旧范围则用完整遗忘登记新 Bank。普通浏览与搜索无需暂停保存和查询。

完整遗忘持久化取消进度和清理代次，超时或重启后继续取消。标记清理完成前，重新查询全部已知操作与文档，再检查 Bank 和操作列表；不存在的查询结果不跨清理调用复用。最终核查按引用编号分页，每组最多并发 4 个请求，每组限时 45 秒；全部引用连续核查，超时后重新核查。清理代次变化时终止旧核查。

删除记录核对失败可触发全局恢复暂停。人工处理方法见 [备份与恢复](DATA-MAINTENANCE.md#异常提示)。

## 数据格式与恢复

业务库 `runtime.sqlite3` 保存窗口、队列和去重。独立 `control.sqlite3` 保存身份、Bank、代次、模式、保存和查询暂停状态、删除日志、采集下限、操作接收凭据和取消意图，不保存聊天正文。

控制格式 5 增加授权、命令摘要凭据、重试意图与宿主接收时间边界。平台原始时间与 AstrBot 在排队前记录的公开 `created_at` 分别核对，不能用首次进入插件的时间替代排队证据。宿主边界持久保存已观测命令的接收时间，模式恢复、遗忘和解除读写暂停继承该高水位，本地时钟回拨不能降低边界。宿主时间只允许一秒未来偏差，与平台原始时间的偏差限制分别核对。命令记录只保存事件键、摘要、原始时间、授权修订、Bank/代次和结果码。用户材料时间来源按逻辑平台映射，OneBot 保留 `onebot.time`，助手保留 `history_observed_at`，已冻结材料不重建。

格式演进沿用既有部署、逻辑身份、Bank、代次、摘要与 operation UUID。缺少历史基线的旧任务不从后来的历史补造助手锚点。格式升级只移除空的 `corrections` 表；若存在历史记录，启动报告 `legacy_corrections_require_handover` 并保留原数据，完成实际数据交接后再升级，不提供通用迁移框架。

## AstrBot 管理视图与安装

`views/memory/` 使用 AstrBot 插件视图 bridge 调用 `core/panel.py` 注册的管理 API，继承 Dashboard 登录与插件访问权限。页面分为「用户与记忆」与「插件设置」，管理连接、账号、Bank 映射、队列、诊断和保存、查询暂停操作；内容管理使用 Hindsight 原生 Control Plane。模型选项只输出标识、名称与兼容结论，服务端通过公开供应商接口生成 Hindsight 配置。

`config.control_plane_url` 保存浏览器可访问的「官方管理地址」，与 `api_url` 分开配置。管理员页面显示可选择复制的地址与「记忆库 ID」（Bank ID）；普通用户命令不输出 CP/API Key。官方 Control Plane 独立登录，采用独立 HTTPS 或 SSH 隧道，不依赖 iframe、SSO、一键外链或插件反代。

配套安装器封装 Hindsight 原生启动与配置，不修改 AstrBot 或 Hindsight 的上游源代码。安装命令打包固定服务模板及服务自身凭据，在 Linux Docker 主机创建独立服务与数据卷，并交付匹配版本的官方 Control Plane；模型配置通过安装后的管理接口提交。容器部署按 AstrBot hostname 识别已有网络，只将配套服务接入该网络。`setup.json` 保存安装标识、服务连接、独立管理密钥和供应商选择。CP 的数据 API Key 与页面访问 Key 分别配置，主机端口仅绑定环回地址，访问步骤见 [部署说明](../deploy/README.md)。

配套「保存并连接」通过显式安装 ID 选择目标资源，不使用浏览器提交的 API 地址或凭据。`setup.json.connection_job` 保存一项接入记录，模型应用、连接配置及插件初始化分阶段核对；任务进度不参与业务配置修订，业务提交后推进预期修订。服务侧完整模型配置指纹使用连接密钥和规范化参数计算 HMAC，识别模型与凭据变化，避免重复应用；不返回完整模型配置。旧模型保存和连接保存接口保持原语义。

`setup.json.connection_mode` 保存显式选择的连接方式；缺少该字段时沿用地址和凭据的归属判断。已有服务模式始终关闭配套管理，即使地址与配套记录相同也不扩大管理范围；切回配套须显式核对安装记录，服务身份及 Bank 不因模式切换而变化。

`deploy/managed_service.py` 在配套容器的 8766 端口提供鉴权管理接口，只能配置本容器的 Hindsight 子进程与私有设置卷。它不挂载 Docker socket。应用配置前从服务侧检查模型，启动失败时恢复先前配置；模型文件原子写入 `models.json`，进程重启后恢复。嵌入身份独立于密钥，指纹变化时拒绝直接复用数据。

连接已有 Hindsight 时，插件只提供接口连接与对应 Bank 的记忆业务，不提供服务级配置或运维。配套管理须匹配安装记录中的 API 地址与连接密钥，初次安装未保存连接时使用专属安装记录。切换服务或使用不同凭据后，旧记录不能开启模型应用、升级、重新部署及卸载；页面入口和后端接口使用相同的归属判断。

插件只写自身配置与数据，配套管理接口只写自身设置卷。宿主全局、对话、供应商和其他插件配置均为读取来源。卸载命令校验专属安装目录、标识和组件列表，删除该服务及其数据；共享外部网络与镜像由宿主管理。

安装设计见 [安装与管理设计](SETUP-DESIGN.md)。
