# 安装与管理设计

本文记录插件管理面板的页面结构、配套部署边界及前后端状态同步约束。

## 页面结构

管理面板（`views/memory/`）分为 **用户与记忆** 与 **插件设置** 两个页签，所有设置直接展开显示（不使用折叠面板，也不直接向浏览器展示服务密钥或拉起带敏感凭据的外部窗口）：

- **用户与记忆**：顶部提供用户选择器与 `+ 添加用户`，下方条带显示当前机器人、旧记忆库选择器（若有）及可复制的 `Bank ID`；核心区置顶为 **记忆模式与状态总览卡**（读写/只读/停用分段切换即时保存，附已保存/待保存/失败计数与最近检索结果）；随后是 **聊天记忆配置** 四张独立保存卡片（细节记忆读取方式、聊天参考与保存、知识页、Reflect 综合推理），以及底部的 **危险操作**（移除用户、清空记忆）。
- **插件设置**：包含 **Hindsight 服务连接**、**全局记忆参数** 与 **部署与迁移信息** 三张卡片。尚未配置连接时 **Hindsight 服务连接** 置顶；连接配置完成后 **全局记忆参数** 移至顶部以便日常调优。

所有可编辑卡片都独立保存并显示「未保存」状态点；破坏性确认弹窗默认聚焦「取消」，并在文案中直接说明受影响的数据范围；操作指南与命令均在页内 `dialog` 完成，配合复制按钮使用（规避宿主 iframe 对 `window.open` 和外链跳转的限制）。

Hindsight 记忆内容的浏览、搜索、单条更正与整库管理全部交由独立访问的官方 Control Plane 承担，Bridge 不在插件页面内重复开发记忆 CRUD 界面。

## 安装与模型配置

### 运行环境判断

后端能力判断决定前端展示的部署入口（页面与 API 共用同一套判断）：
- 宿主机支持 Linux Docker Engine + Compose v2 时，提供「安装配套服务」与「连接已有服务」双入口。
- Windows 原生宿主、WSL2 及 Docker Desktop 容器仅提供「连接已有服务」入口（同时保留旧安装记录的恢复与升级暂停检查）。

### 配套安装与管理端口

Linux 配套部署将数据库、Hindsight 1.2.0 Slim（启动超时等待 75 秒，容器退出宽限 90 秒）、匹配版本的官方 Control Plane 与独立数据卷打包在专属目录（安装时自动生成凭据，`install` 命令仅在生成/展示生命周期内可见，关闭或离开页面后自动从 DOM 清除）。

配套容器内的 `8766` 管理接口仅负责校验模型、启停本容器的 Hindsight 子进程与读写自身设置卷中的 `models.json`，不持有 Docker socket，也不越权修改宿主机或 AstrBot 配置。

- **模型复用与协议转换**：支持 OpenAI Chat/Responses、Azure OpenAI、Anthropic、Gemini 对话，OpenAI/DashScope/Gemini/Ollama 嵌入，以及 DashScope/Cohere/TEI 重排。对非标准上游协议由容器内同进程转换，不将明文模型内容、密钥或上游原始错误写入插件日志。
- **保存并连接**：点击后在后台创建持久化接入任务（`setup.json.connection_job`），分阶段核对安装标识、探测向量维数、验证模型并保存插件配置。浏览器刷新、轮询或插件重载后自动恢复进度展示；同一模型与凭据指纹已就绪时不重复重启容器。若更换嵌入模型或维数，因向量空间改变需先做好数据迁移。
- **归属隔离**：`setup.json.connection_mode` 明确记录当前接入方式。一旦用户切换到「连接已有服务」或更换为外部连接凭据，即使保留了旧安装记录，面板和 API 也会关闭所有配套服务操作（模型修改、重装、升级、卸载与密钥读取），互不干扰。

### 已有服务连接

连接已有 Hindsight 时，插件仅保存 API 地址、API 密钥和管理员用于打开官方网页面板的 `control_plane_url`（与 `api_url` 分开配置）。测试连接与保存连接分开操作，不接管原服务的模型配置、备份或升级。

## 状态轮询、草稿保护与并发锁

- **自动轮询**：页面可见时每 5 秒调用 `bootstrap` 刷新一次（失败后退避至最长 30 秒），页面隐藏时暂停轮询，切回后立即同步。
- **草稿与冲突保护**：轮询与切回标签页不会覆盖用户尚未保存的表单草稿（连接方式、模型选择、全局参数、聊天参考、读取方式、知识页顺序、Reflect 与添加用户弹窗）。保存时校验 `config_revision`、`scope_revision` 及独立选项修订号，若其他页面已修改配置则提示冲突并允许刷新重载。
- **并发请求锁**：界面按键按操作域加锁，跨请求期间拦截旧响应（通过自增 read revision 丢弃切换用户或快速操作前发出的迟到响应）。

## 用户、知识页、工具与 Reflect 交互约束

- **用户列表**：完全由配置名单驱动，不把离线或未授权实例混标为“历史用户”；更换机器人账号后，旧机器人名下的 Bank 收入该用户的「记忆库」下拉选择器，仅支持查看状态、处理暂停或清空，不向新机器人转移记忆。
- **知识页（Knowledge Pages）**：页面通过 `聊天时附带所选知识页` 开关与添加下拉框双向同步状态（兼容原有 `#background-page` 选项与 API 契约，浏览器仅提交有序 `page_id` 列表，服务端从官方目录核对映射）。每行分别展示打包长度检查、目录 `index_stale` 标记及上轮真实使用结果；关闭开关或切换用户会保留/隔离状态，身份或 Bank 变更使原选择失效时给出明确提示。
- **按需工具**：切换 `automatic` / `tools` 独立保存。主模型和全部备用模型明确支持工具调用时启用；任一候选能力未知或不支持时停用按需工具，普通聊天继续。
- **暂停与升级恢复**：
  - 配套升级暂停时，`upgrade_pauses` 单独记录由升级新触发暂停的 Bank，不混入原本就已暂停或停用的用户，确保 **解除升级暂停** 或 **暂不升级** 时精确恢复原状。
  - **查看暂停状态** 弹窗对就绪检查结果设置 30 秒本地过期计时器，任何任务变化、断连或超时都会强制重新向后端核对；存在可丢弃的未发送/失败记录时才显现 **放弃记录** 确认区。
  - Reflect 超时不阻塞读写恢复和清空；格式 7 保持兼容，启动归档历史阻塞态。

## 卸载边界

配套服务卸载采用二段确认（勾选确认彻底删除全部数据后再生成命令），命令执行时仅校验并清理该次安装专属的容器、专属网络、数据卷和安装目录，不触碰外部共享网络、公共镜像、Docker 引擎或 AstrBot 自身目录。插件本体的移除由 AstrBot 插件管理完成。
