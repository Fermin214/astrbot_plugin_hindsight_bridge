# 安装与管理设计

## 使用目标

Linux 用户从 AstrBot 插件管理安装 Hindsight Memory，在插件详情的「记忆管理」视图完成设置和日常管理。Windows 用户部署支持安排在后续版本；Docker Desktop 仅用于开发验证。

首次设置提供两个入口：

1. 安装配套服务：选择 AstrBot 已配置的对话和嵌入模型，可选重排模型；生成完整安装命令，在运行 AstrBot 的 Linux 主机粘贴一次，回到视图连接并启用。
2. 连接已有服务：填写 Hindsight API 地址与服务 Key，再选择允许使用记忆的账号。

配套安装负责生成服务密钥、数据库配置、稳定标识和 Docker 网络。平台实例从 AstrBot 配置选择，使用者填写自己的 QQ 号；高级参数使用默认值。向导检查连接与必需的对话配置，聊天从启用后的新消息开始。

## 模型配置

配套服务复用 AstrBot 的供应商配置。页面只显示名称、模型和适配结果，服务端读取所选供应商的地址、密钥及向量维数。未知协议和无法保持行为的自定义选项须给出明确原因，不能换用另一个模型。

对话协议复用 Hindsight 1.1.0 的 OpenAI Chat、Responses、Anthropic 和 Gemini 实现。额外参数、请求头、Azure 部署配置及思考参数按协议传入。百炼原生、Gemini 和 Ollama 嵌入，以及百炼原生和 TEI 重排，通过独立的内部转换进程处理；按需使用同一个固定版本 Hindsight 镜像运行，无额外依赖和主机端口。转换进程逐项保留地址、认证、代理、维度发送方式与参数，检查向量长度、顺序和重排索引，不修改向量数值。

模型转换配置只进入安装命令与受限环境文件。转换进程使用服务密钥校验内部请求，不记录请求正文、密钥或上游错误。AstrBot 和 Hindsight 的共享 Docker 网络同时提供给转换进程，保证容器模型地址和重建后的网络连接可用。

嵌入身份独立于内部传输地址和密钥。已有 OpenAI 配置沿用原来的指纹算法，增加内部转换或更换密钥不触发向量迁移；改变原始嵌入协议、地址、模型、参数或维数时阻止复用数据。重复安装同时校验数据库身份、服务身份和嵌入指纹。

已有 Hindsight 服务沿用自身模型配置。配套服务更换模型配置后重新生成安装命令；稳定身份与数据卷沿用。向量模型或维数改变需要数据迁移。

## 管理能力

视图提供服务状态、用户选择、记忆列表与详情、搜索、导出、更正、开启、只读、暂停和完整遗忘。日常管理在 AstrBot 内完成；Hindsight 自带网页可供服务维护使用。

管理操作遵守现有身份、队列、恢复和删除机制。面板管理员提交的更正明确记录管理员来源，不能冒充私聊用户原文。完整遗忘使用限时确认并核对用户范围与代次。

## 完成标准

- 干净的 Linux 环境可通过生成的安装命令运行配套服务，无需手动编辑环境文件或 Docker 网络。
- 选择已有 AstrBot 模型即可部署，普通设置不要求重复填写模型地址和 Key。
- 无后端、模型类型不匹配、连接失败、错误密钥和不兼容对话设置均有可执行的中文提示。
- 管理视图在正式 AstrBot 插件视图中运行，桌面和移动端均可操作。
- 安装、重载和更新保持记忆归属与数据；更正、模式与遗忘复用可靠核心。
- 接入已有服务与首次安装分别通过实际集成验证，日常聊天自动保存并召回记忆。
