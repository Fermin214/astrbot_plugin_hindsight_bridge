# 安装与管理设计

## 页面结构

面板提供两个标签：「记忆管理」与「设置」。记忆管理用于用户选择、Bank 映射、模式、队列、诊断、维护与完整遗忘；设置承载安装、服务连接、模型、使用者、运行状态与卸载。缺少连接配置时直接进入设置引导；完成后默认进入记忆管理。

记忆内容的浏览、搜索、更正、删除、Bank 管理和原生导入导出由独立打开的官方 Control Plane 提供。插件不再实现内容列表、详情、更正表单或下载页面。已有 QQ view/show/export 只保留本人范围与官方只读 API 转发。

首发为同机 Linux、AstrBot 4.29.1 内置执行器 `local`、OneBot v11（`aiocqhttp`）私聊纯文字和 Hindsight 1.1.0。模型协议适配、配置管理器和原子回退沿用已有实现。

插件总开关使用 AstrBot 插件面板的启停。空配置可加载，完成配置前不采集；关闭插件通过终止钩子停止队列与采集并释放资源。

## 安装与模型配置

Linux 配套安装先部署数据库、Hindsight 运行管理器、匹配版本的官方 Control Plane 及独立数据卷。连接凭据由后台自动生成和保存，安装命令不包含模型密钥。含凭据命令由管理员显式生成，在复制、关闭、离开设置或隐藏页面后清除展示。安装入口始终可用，不依赖配套服务是否在线；卸载后可重新安装。

配套安装模式下模型选择区始终显示，复用 AstrBot 已配置的对话、嵌入和可选重排供应商。页面只显示模型标识、名称与适配结果。保存时先检查配套服务；尚未安装则提示执行安装命令。后台读取配置并探测实际向量维数，先验证配套服务安装身份，再经鉴权管理接口提交模型配置。服务侧验证模型、启动 Hindsight 并保存私有配置；失败时恢复先前配置。

管理器只能控制本容器的 Hindsight 子进程与自己的设置卷，不需要 Docker socket 或主机配置写权限。模型保存独立于安装，日常修改不重新生成安装命令。嵌入协议、地址、模型、参数或维数变化需要向量迁移；密钥轮换不改变嵌入身份。

对话协议支持 OpenAI Chat、Responses、Anthropic 与 Gemini。百炼原生、Gemini、Ollama 嵌入及百炼原生、TEI 重排等请求通过同容器的内部协议转换处理。转换保留地址、认证、代理、维度发送方式与请求参数，不记录模型正文、密钥或上游错误。

已有 Hindsight 通过 API 地址和服务密钥连接，并单独填写 `control_plane_url`；模型与官方 CP 由该服务维护，插件不提供其模型配置与卸载操作。

「验证并保存模型」提交后台任务，页面查询验证与启动进度；相同请求标识重复提交时复用任务结果，处理中相同模型选择复用任务。插件退出时取消任务并释放资源。「测试服务连接」仅用于已有服务，检查连接与鉴权。

## 独立官方管理访问

`config.control_plane_url` 是管理员浏览器可访问的地址，与服务侧 `api_url` 分开保存，不能按容器名称或端口机械推导。插件显示可选择复制的地址和 Bank，不传递 CP/API Key 给普通用户。Control Plane 独立登录，页面访问 Key 与服务 API Key 分开管理，地址中不携带凭据。

有域名使用独立 HTTPS 入口，无域名使用 SSH 隧道连接服务器环回端口。首发不要求 iframe、SSO、一键外链或定制子路径。安装器的代理与 Control Plane 服务、独立密钥和环回端口由 [部署说明](../deploy/README.md) 定义。

## 状态与维护

页面可见时每隔约五秒获取状态，请求失败后逐步延长至三十秒，恢复后继续正常更新。隐藏页面暂停查询，返回页面后恢复。自动获取状态保留未保存的模型、账号与模式选择。

管理页显示账号、Bank、模式、队列、错误和维护状态；内容更新由官方 Control Plane 展示。

维护冻结新采集、助手回调、召回注入、提交和重试，已接受任务继续正常排空。未提交旧待办需要显式作废；有响应不明或协作取消不确定时，恢复入口保持阻止状态。官方内容操作后核对 Bank 并清理短期语境，再显式恢复维护。浏览与搜索不要求维护。

既有 Bank 丢失时报 `bank_missing`，不能自动重建。恢复原 Bank 后显式恢复维护，或使用完整遗忘登记新 Bank；完整遗忘继续依靠独立控制日志、新代次和持续清理。恢复核对失败可安全暂停，由管理员按 [数据维护](DATA-MAINTENANCE.md) 手工恢复，不重构全局恢复流程。

## 配置与消息边界

平台实例从 AstrBot 读取，权限仅接受明确的平台实例与用户组合。保存使用者后即进入记忆管理列表；通过 OneBot 登录信息取得真实机器人账号后创建记忆身份，不需要先发送消息。机器人离线或服务恢复期间保留用户入口，说明连接或恢复要求，不伪造机器人身份。

消息时间跟随 AstrBot 全局 `timezone`，宿主未设置或值无效时按消息发生时刻使用系统本地时区。插件初始化和权限刷新时读取宿主设置，不受时间感知提示开关影响，不提供独立时区字段；已冻结的提交材料不随宿主设置改变。时间与身份提醒通过插件自身的结构化内容解析适配，宿主及其他插件的设置不参与写入。

## 卸载

服务维护直接展开，提供重新部署与完整卸载命令。用户确认删除全部记忆数据后生成，复制、关闭或离开页面后清除展示，需要时重新生成。脚本检查安装标识、目录真实路径、服务列表和专属数据卷，移除该安装的容器、专属网络、数据卷与文件。外部网络、共享镜像、AstrBot 与 Docker 不属于删除范围。插件本体通过 AstrBot 的卸载入口移除。

## 数据与恢复

配套设置卷保存模型参数和凭据，数据库卷保存记忆；备份须同时覆盖二者与插件身份、队列、控制状态。重新安装服务文件沿用身份和数据卷。内容更正以 Hindsight 原生结果为准，本地更正不参与召回、查看或导出。历史更正非空时，启动报告 `legacy_corrections_require_handover` 并保留数据，完成实际数据交接后继续。
