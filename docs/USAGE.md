# 使用与管理记忆

完成设置后，直接与机器人正常聊天。插件保存适用的文字对话，并在后续聊天时查找相关记忆。用户原文与标准持久化 history 中关联的最终助手正文分别保存；助手正文的发送状态为 `unknown`，不能据此认定 QQ 送达或操作成功。

## 管理入口

打开 **Hindsight Memory 插件详情 → 记忆管理**。插件页管理连接、使用账号、Bank 映射、模式、队列、诊断、维护与完整遗忘；「设置」提供安装、模型、连接和配套服务维护。总开关使用 AstrBot 插件面板的启停。

记忆内容由独立打开的官方 Control Plane 管理。管理员在插件页选择用户，复制对应 Bank 和官方管理地址 `control_plane_url`，在浏览器中独立登录，找到该 Bank 后浏览、搜索、更正、删除或使用原生导入导出。API 地址和浏览器管理地址分别配置；使用独立 HTTPS 或无域名 SSH 隧道，详见 [安装指南](INSTALL.md#独立访问官方-control-plane)。

插件页只显示可选择复制的管理地址和 Bank，不要求 iframe、SSO 或一键外链。面板登录密钥和 API Key 不通过普通用户命令传递。

## 官方内容维护

浏览、搜索不需要进入维护。更正、删除、清空、重处理或导入等内容写入操作前，管理员应：

1. 在插件管理页对对应用户开始维护，冻结新采集、助手回调、召回注入、提交和重试。
2. 等待已接受任务正常排空，显式作废未提交旧待办，再执行官方内容操作。
3. 操作后核对 Bank 映射，在插件管理页显式恢复维护，再选择记忆模式；过时的短期语境随恢复清理。

响应不明或协作取消仍有不确定性时保持暂停；无法确认旧任务时，使用完整遗忘，通过控制日志、新 Bank 代次和持续清理恢复。官方删除既有 Bank 后不会自动重建；可恢复原 Bank 后显式恢复维护，或完整遗忘登记新 Bank。完整步骤见 [数据维护](DATA-MAINTENANCE.md#官方内容维护)。

## QQ 私聊命令

命令只操作发消息者对应的 Bank，不能自行指定其他 Bank。日常聊天无需逐条保存或手动搜索。

| 命令 | 用途 |
| --- | --- |
| `/hindsight help` | 查看帮助 |
| `/hindsight status` | 查看连接、模式、队列、维护与清理信息 |
| `/hindsight view [页码]` | 调用官方只读 API 查看本人记忆，每页 10 条 |
| `/hindsight show 记忆ID` | 查看官方记忆详情、类型、时间和来源 |
| `/hindsight recall 问题` | 搜索本人记忆 |
| `/hindsight export` | 从官方 API 导出本人事实、整合观察与源文档 |
| `/hindsight retry` | 故障处理后重试本人的失败任务 |
| `/hindsight cancel 任务编号` | 取消指定上传任务，编号从 `status` 取得 |

“整合观察”是 Hindsight 从多条记忆中整理出的结果。聊天材料在后台处理，不会立即显示。查看、召回和导出均以官方结果为准，不叠加本地更正。

`/hindsight correct` 旧命令只提示联系管理员，在官方 Control Plane 中更正，不提交本地更正材料。管理员操作前先完成维护流程。

## 暂停与恢复

| 效果 | 命令 | 记录新内容 | 聊天时自动使用已有记忆 |
| --- | --- | --- | --- |
| 正常使用 | `/hindsight on` | 是 | 是 |
| 只用已有记忆 | `/hindsight readonly` | 否 | 是 |
| 暂停自动记忆 | `/hindsight pause` | 否 | 否 |

只读和暂停保留已有记忆，允许手动查看、搜索和导出；维护、Bank 丢失或恢复检查会额外阻止这些读取。只读和暂停冻结未提交队列，恢复开启后继续处理同代次有效待办；已接受任务仍可完成。暂停期间的聊天不补录。

维护冻结与个人模式分别管理。`/hindsight on` 不能解除维护或修复丢失的 Bank，需管理员完成维护恢复。

## 导出

`/hindsight export` 通过 QQ 发送 UTF-8 JSON，包含本人的事实、整合观察和相关源文档，不添加本地更正记录。单次最多 10,000 条记忆、8 MiB；内容变化、来源缺失或超限时显示错误。管理员也可使用官方 Control Plane 原生导出。

个人 JSON 不包含上传队列、AstrBot 聊天历史、独立控制库或全部服务配置，不能替代 [完整备份](DATA-MAINTENANCE.md)。QQ 文件上传配置见 [安装指南](INSTALL.md#导出-json-文件失败)。

## 完整遗忘

发送 `/hindsight forget`，按回复在 120 秒内发送 `/hindsight forget 确认码`。插件先持久化控制日志，停用旧范围、作废本地旧队列、登记新 Bank 代次，协调取消旧任务、删除旧 Bank 并持续清理。协作取消不能单凭 `cancelled` 证明任务退出，旧 Bank 永不复用。

清理期间保持暂停，连接恢复后继续删除，进度从 `/hindsight status` 查看。完成后用 `/hindsight on` 从新消息开始积累记忆。完整遗忘不删除 AstrBot 自身的聊天记录。

## 故障处理

先发送 `/hindsight status`，把错误码交给管理员。`bank_missing`、`maintenance_active`、`maintenance_pending`、`maintenance_unknown_operation` 和 `legacy_corrections_require_handover` 的处理方法见 [数据维护](DATA-MAINTENANCE.md#异常提示)。

取消任务停止后续提交并核对已经发出的请求，已形成的记忆仍保留。任务接收或取消结果不明时保持暂停，不反复重试；需要清除所有旧材料时使用完整遗忘。
