# 使用与管理记忆

完成设置后，直接与机器人正常聊天。插件保存私聊文字和机器人最终回复，供后续聊天查找。

在 **用户与记忆** 点击 **添加用户**，选择平台实例、填写用户 ID，再确认机器人身份。点击 **移除用户** 后立即撤销访问权限并从选择器移除，已有记忆保留；重新添加或更换机器人登录账号后须再次确认，仅接收确认之后的新消息。

OneBot 使用用户 QQ 号；官方机器人 WebSocket 与 Webhook 使用私聊 `/sid` 返回的用户 UID（OpenID）。各入口使用相同命令。图片和引用由 AstrBot 处理，不自动保存为记忆。

## 管理入口

打开 **Hindsight Bridge 插件详情 → 记忆管理**。页面分为 **用户与记忆** 和 **插件设置**。

在 **用户与记忆** 顶部选择用户，点击 **读写记忆 / 只读记忆 / 停用记忆** 直接切换模式。下方显示 Bank ID、聊天知识页、已保存、待保存与失败数量、最近检索时间；发生失败时显示具体原因和 **重试保存**。末尾提供 **移除用户** 与 **清空记忆**。

**已保存** 统计插件确认成功的聊天材料：用户消息和助手最终正文分别计数，不是 Hindsight 的事实或观察数量。计数限于所选用户及所选记忆库的有效代次，清空后重新计数；没有可用范围时显示待开通或暂无数据。

配套部署的 **插件设置** 提供模型配置、连接与访问、服务管理，以及通用的 **记忆与知识页设置**。模型使用 **记忆处理模型 / 向量模型 / 重排模型** 命名；记忆处理模型负责 Hindsight 的记忆提取、整理和生成，向量模型负责语义检索，重排模型可不使用。连接已有服务时，同样可以保存插件的记忆参数；服务级模型与运维由服务管理员负责。

### 调整记忆参数

在 **插件设置 → 记忆与知识页** 调整长度和超时，点击 **保存**。设置直接生效。

同一区域还提供以下参数：

| 参数 | 默认值与范围 | 作用 |
| --- | --- | --- |
| 查询 token 上限 | 380，范围 32–400 | 限制发送给 Hindsight 的查询长度，优先保留用户消息 |
| 查询分词编码 | `o200k_base` | 使用 tiktoken 编码名称计算查询及记忆参考长度；保存时校验并加载 |
| 待保存记录数量上限 | 10000，正整数 | 达到上限后停止接收新记录，已有记录继续处理 |
| 待保存内容容量上限 | 64 MiB，正整数 | 限制本地待处理正文容量；调低后保留积压，容量释放后继续接收 |
| 额外排除的命令前缀 | 留空，逗号分隔 | 排除后续匹配消息；以 `/` 开头的消息始终排除 |

轮询与列表刷新保留未保存内容。其他页面修改配置后，面板提示冲突；点击 **重新加载记忆设置** 会以最新保存值替换该表单草稿。连接与模型表单分别保存。

**部署与迁移信息** 显示服务识别码、记忆归属识别码、服务地址变更序号和控制目录。这些项目在标准插件配置中管理，修改前按 [备份与恢复](DATA-MAINTENANCE.md) 执行迁移。

## 在官方面板修改记忆

在 **用户与记忆** 复制 **Bank ID**，到 **插件设置 → 连接与访问** 复制 **Hindsight 管理地址**，在浏览器打开后找到对应记忆库。官方面板直接提供浏览、搜索、更正、删除、导入和导出，普通内容操作不需要暂停插件或服务，也不改变记忆模式。

**Bank 是按机器人和用户隔离的记忆库**，首次保存聊天时由插件创建。同一用户更换机器人后，旧库放在 **记忆库** 选择器中，以机器人账号区分；旧库不能切换模式或重试保存，不会转给新机器人使用。

统一的 **Hindsight 管理地址** 在 **插件设置 → 连接与访问** 保存。API 地址供 AstrBot 连接服务，管理地址供管理员浏览器访问，两者分别配置。Control Plane 独立登录，插件页不展示登录密钥。服务器面板需要 HTTPS 域名反向代理或 SSH 隧道；浏览器中的 `127.0.0.1` 指管理员自己的电脑。访问和获取 `HINDSIGHT_CP_ACCESS_KEY` 的命令见 [安装指南](INSTALL.md#独立访问官方-control-plane)。

需要完整删除用户记忆时，使用插件的 **清空记忆**，同步作废来源材料和待保存记录，避免旧记录再次写入。直接在官方面板删除 Bank 会触发 `bank_missing`；恢复原 Bank 后，在 **查看暂停状态** 中点击 **核对记忆库**；已有读写暂停时，等检查通过后再解除。也可使用清空记忆流程重新开始。

升级或故障留下的读写暂停会显示 **查看暂停状态**。页面自动检查已发送任务；检查失败时显示原因和 **重试检查**。可放弃的记录通过勾选确认后点击 **放弃记录** 处理；已发送但结果不明的记录不能放弃。检查通过后点击 **解除读写暂停**，原记忆模式保持。已移除用户仍有暂停时，通过顶部的暂停提示处理。它是异常与升级恢复入口，不是第四种记忆模式。

## QQ 私聊命令

命令操作当前机器人下本人的记忆。日常聊天无需逐条保存或手动搜索；收到确认过期或重发提示时，重新发送命令即可。

| 命令 | 用途 |
| --- | --- |
| `/hindsight help` | 查看帮助 |
| `/hindsight status` | 查看连接、模式、队列、暂停与清理信息 |
| `/hindsight view [页码]` | 查看本人记忆，每页 10 条，默认第 1 页 |
| `/hindsight show 记忆ID` | 从列表复制记忆 ID，查看这条记忆的详情、时间和来源 |
| `/hindsight recall 问题` | 搜索本人记忆 |
| `/hindsight background [序号]` | 按所选顺序只读查看本人知识页、开关和刷新记录，默认第一篇 |
| `/hindsight export` | 导出本人记忆和来源材料，得到 JSON 文件 |
| `/hindsight retry` | 故障处理后重试本人的失败记录，与插件页“重试保存”作用相同 |
| `/hindsight cancel 任务编号` | 取消指定保存任务，编号从 `status` 取得 |

### Hindsight 原生名称

插件沿用 Hindsight 1.1.0 / 1.2.0 官方 Control Plane 的内容名称，中文与英文对应如下：

| 名称 | 用途 |
| --- | --- |
| 记忆库（Bank） | 每个用户的独立记忆范围，以 Bank ID 定位 |
| 世界事实（World Facts） | 来自外部的人、事物和事件等事实 |
| 经历（Experience） | 记忆库所属 Agent 自己的行为与经历 |
| 观察（Observations） | Hindsight 通过整合（Consolidation）从事实生成的知识 |
| 知识库 / 知识页（Knowledge Base / Knowledge Page） | 按文件夹组织、由 Hindsight 生成和更新的主题文档 |
| 心智模型（Mental Model） | 原生主题知识模型；知识页也是一种心智模型 |
| Control Plane | Hindsight 官方记忆管理面板 |

Retain 用于保存材料并提取记忆，Recall 用于召回相关记忆，Reflect 用于根据记忆生成回答和知识页。插件的“保存”“检索”“聊天时使用所选知识页”描述具体动作，不是另外的 Hindsight 内容类型。名称来源见 [官方中文界面](https://github.com/vectorize-io/hindsight/blob/v1.2.0/hindsight-control-plane/src/messages/zh-CN.json) 和 [知识页文档](https://hindsight.vectorize.io/developer/knowledge-pages)。

新材料经后台处理后出现在记忆中；查看、搜索和导出均读取官方服务。

列表和详情是有长度限制的预览，过长内容会省略。需要完整内容时，使用 `/hindsight export` 或官方 Control Plane；平台无法发送长文本或文件时，改用官方页面。

更正记忆由管理员在官方 Control Plane 操作。

## 暂停与恢复

| 效果 | 命令 | 记录新内容 | 聊天时自动使用已有记忆 |
| --- | --- | --- | --- |
| 读写记忆 | `/hindsight on` | 是 | 是 |
| 只读记忆 | `/hindsight readonly` | 否 | 是 |
| 停用记忆 | `/hindsight pause` | 否 | 否 |

“只读记忆”和“停用记忆”都会保留已存记忆，允许手动查看、搜索和导出；保存和查询暂停、记忆库丢失或数据恢复检查期间，这些查询也会暂停。两种模式都暂停发送等待中的记录，切回“读写记忆”后继续保存仍有效的记录；服务已接受的任务仍可完成。这两种模式下的新聊天不补录。

升级或故障造成的读写暂停独立于记忆模式；在 **查看暂停状态** 中解除后，记忆模式保持原值。普通模式切换不解除这类暂停。

## 导出

`/hindsight export` 通过 QQ 发送 UTF-8 JSON，包含本人的世界事实（World Facts）、经历（Experience）、观察（Observations）和相关源文档。单次最多 10,000 条记忆、8 MiB；数据较多时可使用官方页面导出。

个人导出不包含知识页及其历史。插件运行库、最新控制库和配套服务的保存方法见 [备份与恢复](DATA-MAINTENANCE.md)。QQ 文件上传配置见 [安装指南](INSTALL.md#导出-json-文件失败)。

## 清空记忆

管理员在 **用户与记忆** 点击 **清空记忆**，核对用户与删除范围，勾选确认后点击 **确认清空**。用户也可以在 QQ 私聊发送 `/hindsight forget`，按回复在 120 秒内发送 `/hindsight forget 确认码`。

清空会删除此用户的全部长期记忆、知识页及其历史、来源材料和待保存记录，无法恢复；AstrBot 自身的聊天记录、工具历史和日志保留。

清理期间保持暂停，服务连接恢复后会继续删除，进度可在插件页或 `/hindsight status` 查看。清理完成后，重新选择“读写记忆”或发送 `/hindsight on`，从新消息开始积累记忆；新记忆库在首次保存聊天时自动创建。

## 可选知识页

插件可以将用户 Bank 中最多 8 篇 **知识页（Knowledge Page）** 作为临时参考传递给聊天请求，默认关闭。自动记忆召回（Recall）负责问题相关的记忆检索，知识页补充管理员选定的主题文档。知识页由 Hindsight 生成、刷新和存储，Bridge 只管理选择与传递。

### 配置

1. 在 Control Plane 选择用户的 Bank，进入 **知识（Knowledge）→ 知识页（Pages）**，在 **知识库（Knowledge Base）** 点击 **新建知识页（New page）**。填写名称和 **源查询（Source query）**，即希望此页回答的问题，创建后等待正文生成。
2. 确认来源范围和正文。需要缩短正文时，打开该页的 **心智模型选项（Mental model options）**，点击 **编辑（Edit）**，在 **概览（General）** 调低 **最大令牌数（Max Tokens）** 并保存。重新打开「心智模型选项」，在操作菜单点击 **立即完整刷新**，再确认 **执行完整刷新**，等待生成并核对正文长度；普通手动刷新可能保留原正文。`tags` 按原生过滤规则配置；使用未打标签的既有记忆时，保持标签为空。创建和刷新按 Hindsight 模型配置产生调用费用。
3. 在插件页 **用户与记忆 → 记忆内容 → 聊天知识页** 选择知识页，选择新页面即添加；用 **上移 / 下移** 调整优先顺序，**移除** 只取消这篇引用，原生页已删除时也能逐个移除。每次操作立即保存。选择 **不使用知识页** 停止传递全部页面，顺序仍保留；重新选择已有页面即可开启。列表在选择用户后自动读取。
4. 使用 `/hindsight background` 读取第一篇已选正文、开关、刷新及失败时间；`/hindsight background 2` 读取第二篇。该既有命令保留兼容，不是 Hindsight 的原生功能名称。

### 自动读取与内容更新

- 每篇知识页的独立长度上限为 `background_max_tokens`，默认 400 token，含正文、说明与元数据，范围 64–8192。按所选顺序放入完整页，放不下时跳过该页并继续尝试后面的页面，再按检索顺序放入完整记忆条目；不截断或自动摘要。列表逐页显示长度、目录更新标记和上次聊天是否使用，单页失败不会掩盖其他页面的结果。
- 知识页、检索结果与状态说明共用 `recall_max_tokens` 和 `context_max_chars`：默认 1200 token、4000 字符，可分别调至 8192 token、32768 字符。在 **插件设置 → 记忆与知识页设置** 调整；例如较长页面可设为知识页 4096 token、共享 6000 token 和 24000 字符。增加上限会提高聊天模型的上下文用量。
- `background_timeout` 为全部所选知识页共用的读取子限时，默认 1 秒，范围 0.05–10 秒；实际不超过认证后剩余 `recall_timeout` 的四分之一。最多同时读取 4 篇，排队等待也计入同一子限时。页面与 Recall 并行，总等待仍由 `recall_timeout` 限制，默认 10 秒。服务较慢时可同时调整两项；超时后保留已完成的页面与检索结果，普通聊天继续。
- 选择知识页、调整顺序后点击 **保存**。页面显示含包装的 token 用量与上限；字符超限时另行标出。点击 **调整长度** 修改并保存上限，再返回用户页点击 **刷新知识页**。发送新消息后，页面行内显示实际使用结果。正文为空时等待原生生成，持续为空时检查来源和标签。
- 自动路径读取原生 `detail=content`，Hindsight 1.1.0 / 1.2.0 在该路径返回的 `is_stale` 为 null，正文新鲜度未知。插件单独展示读取目录时的更新标记，不能据此保证正文已包含全部记忆；内容更新在 Control Plane 核对。
- 选择「不使用知识页」后不再向聊天模型传递正文，原生知识页和引用保留。「停用记忆」模式停止自动传递，手动查看保留；升级或故障造成的读写暂停，以及清空记忆期间，停止所有内容读取。重新授权或完整遗忘后重新选择。
- 内容更正、源事实删除和重处理在官方面板操作，核对 Bank 内整合/刷新任务及页内容。插件暂停期间，Hindsight 原生后台刷新按自身设置运行。

个人 JSON 导出包含世界事实、经历、观察及其引用源文档。知识页正文和版本历史随 Hindsight 数据库备份。

知识页区域显示上次聊天是否实际使用了所选页面；列表加载后仍保留使用结果。页面太长、读取超时、正文为空或页面不存在时，显示原因与处理方法。身份或记忆库变化后需重新选择，原选择不会自动恢复。

## 按需记忆工具

在 **用户与记忆 → 记忆内容 → 细节记忆** 选择读取方式并点击 **保存**。默认 **自动召回** 根据消息检索相关事实；**按需工具** 让 AstrBot Agent 决定何时搜索知识页、分段读取原文、查找事实或查看来源与最近版本。

读取方式按用户保存，重载后保留，可在聊天前配置。实际聊天时检查内置执行器、模型工具支持和会话工具列表；模型不支持工具、会话排除记忆工具、存在子代理交接或配置回退模型时，面板显示不可用，可切回自动召回。

两种读取方式共用原有身份与记忆模式。读写模式仍保存新聊天，只读模式只读取，停用模式不开放 Agent 记忆工具；维护、完整遗忘、来源变化和记忆库缺失也会阻止读取。自动知识页独立工作；本人显式 `/hindsight recall` 等只读命令保留原有语义。

| 工具 | 功能 |
| --- | --- |
| `hindsight_bridge_search_pages` | 搜索本人 Bank 中的知识页，最多 5 条原生摘要；排序分数只用于同次查询 |
| `hindsight_bridge_read_page` | 按完整原文行读取知识页，可读取未选为自动参考的页面 |
| `hindsight_bridge_recall` | 通过原生 Recall 检索事实，保留来源编号、归因和时间 |
| `hindsight_bridge_page_sources` | 读取知识页原生来源编号，缺失时明确返回 |
| `hindsight_bridge_page_history` | 读取最近最多 5 条原生版本或刷新失败记录，并标明范围 |

长页首段从第 1 行开始，返回内容版本和下一行号。续读必须携带这两项；页面更新后从新版第一行重新读取。每段保留完整行，单行超限时请管理员通过官方面板查看。模型未调用工具与读取失败分别显示，未调用不等于没有相关记忆。

每条原始消息共享最多 4 次记忆工具调用，续轮不另开额度。单次最长等待为 3 秒，且不超过记忆检索等待设置；单次结果最多为共享 token 上限、共享字符上限及 8 KiB，累计不超过共享 token 上限的两倍和 16 KiB，均包含说明与元数据，并预留简短的额度提示。额度用完后移除这条请求中的记忆工具，普通聊天继续。工具账本在主 Agent 完成时关闭，最长保留 120 秒；超时或额度用完后可发送新消息继续。

来源和版本来自 Hindsight。刷新失败记录不是新版本；过长历史版本只返回明确标记的元数据，最近记录也不是完整历史。原生历史没有服务端分页，整体响应超过 256 KiB 时停止读取；正文仍可单独读取，完整历史请在 Control Plane 查看。知识页创建、编辑和刷新继续由官方面板管理。

工具查询与结果可能进入 AstrBot 的会话历史、日志及其外部收集副本。Bridge 不将直接工具响应和工具调用作为新增聊天材料；机器人最终回复仍按助手陈述保存，可能复述读到的内容。清空 Bridge 记忆保留宿主会话、工具历史及日志；这些记录的管理使用 AstrBot 自身机制。

## Reflect

在 **用户与记忆 → 记忆内容** 开启 **Reflect**，设置等待秒数后点击 **保存**。默认关闭，等待默认 12 秒，可设为 3 到 30 秒；可在聊天前配置，保存后用于后续聊天，重载保留。未点击保存的修改只保留在页面中；配置冲突时刷新页面后修改。

Reflect 使用 Hindsight 的原生模型和检索综合复杂问题，并返回答案、官方来源及原生报告的用量。它不替代自动 Recall，也不创建另一套 AstrBot Agent。自动召回与按需方式均可独立开启 Reflect；记忆库须先通过普通聊天保存建立。停用、维护、身份或设置变化后不交付旧结果。

每条原始消息最多调用一次 Reflect，与其他记忆工具共用 4 次调用及累计输出额度。答案保持原生正文，来源每类最多显示 5 条并注明可用数量；过长结果报错，答案不截断。没有原生用量时显示未知，不估算费用。Reflect 的查询、结果和原生反思记录可能保存在宿主会话、日志及 Hindsight 中。

等待到期后普通聊天继续，已发送的原生请求仍由插件跟踪，传输任务最长 120 秒。原生响应晚到只用于关闭执行屏障，不回填聊天；模型调用费用可能继续产生。完整遗忘先停止旧范围的新请求，再等待已发送请求的执行终点，最后删除旧 Bank。关闭 Reflect 不会解除已发送请求的清空屏障。

Hindsight 1.1.0 和 1.2.0 没有公开的 Reflect 请求完成查询。断网、进程退出、异常代理响应或无法识别的响应使执行终点不明时，相关旧 Bank 保持清空等待，不自动重发。恢复需要可核验的原生请求完成凭据；重复查询 Bank、等待固定时长或删除请求记录不能替代该凭据。其他用户的记忆流程继续按各自状态运行。

## 故障处理

先发送 `/hindsight status` 查看状态，将错误提示交给管理员。处理方法见 [备份与恢复](DATA-MAINTENANCE.md#异常提示)。

取消任务会停止后续发送，并继续核对已经发出的请求，已形成的记忆仍保留。任务接收或取消结果不明时保持暂停，不反复重试；需要清除所有旧材料时使用清空记忆。
