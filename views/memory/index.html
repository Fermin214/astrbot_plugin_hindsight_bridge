备份与恢复

  1. 停止写入

    手工备份先停用插件；配套升级点击「暂停插件读写」，保持插件与配套管理接口可用。两种方式都需停止其他客户端、官方面板和定时任务写入，等待已接收任务和后台任务结束。手工备份停止 Hindsight 服务，保留数据库运行；配套升级的停机与数据库备份由升级命令完成。

  2. 备份插件数据

    在 AstrBot 的 Python 环境中执行。示例使用容器内默认路径；按实际安装位置和控制目录修改，将 YYYYMMDD-HHMMSS 换成备份时间，输出目录须为新目录。Docker Compose 部署可在 AstrBot 的部署目录加上 docker compose exec -T astrbot 前缀，服务名按实际配置替换。

    另存插件配置 data/config/astrbot_plugin_hindsight_bridge_config.json 和业务目录中的 setup.json。自定义控制目录以 control_state_dir 为准。

  3. 备份配套服务数据和配置

    用 PostgreSQL 备份工具导出配套服务数据库，数据库服务名为 memory-db；另存原安装目录、覆盖文件和 memory_settings 卷中的 models.json。Bank 导出用于内容迁移，升级恢复还需完整数据库备份。

  4. 核对恢复与保存副本

    在独立环境恢复，核对原 Bank、来源材料、知识页和任务，将备份复制到服务主机之外。

    升级前备份完成后保持停写，返回升级窗口，完成升级和结果核对后再恢复写入。日常备份完成后，按原部署方式启动服务，在 AstrBot 插件面板启用插件，确认恢复检查通过后再恢复其他客户端写入。

    恢复旧业务快照时沿用最新控制库、原 service_id 和账号对应关系，防止已清空的记忆重新写入。

升级 Hindsight

  1. 暂停插件读写

    暂停期间的新聊天不会保存，普通聊天继续。

  2. 备份并执行升级

    先备份插件配置、业务数据和最新控制数据，停止其他客户端及官方面板写入，等待已接收任务和后台任务结束。升级命令另会备份服务配置、模型设置和数据库。

    在原服务器、原安装目录执行。升级失败时保持暂停，用升级前配置及数据库备份恢复，再核对连接和旧记忆。

  3. 核对并结束升级

    命令执行成功后核对版本、旧记忆和模型配置，再解除升级新增的暂停。

暂停状态

放弃尚未发送或保存失败的记录，无法恢复。已接收的任务继续处理；所选记忆库保持读写暂停。
